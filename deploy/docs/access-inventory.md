# Перечень доступов

Собрано с боевого сервера 26.09.2026. **Секретов здесь нет** — только
где они лежат, кто владелец и что сломается при смене.

Все значения, если не сказано иное, живут в одном файле:

```
/var/www/modelizmclub/backend/.env       права 640 root:www-data
```

Всего в нём 127 ключей. Права `640` с группой `www-data` поставлены
08.09: до этого файл был `600 root:root`, php-fpm его не читал, и
приложение держалось на собранном кеше конфигурации. Любая чистка кеша
клала API — так и случилось 07.09, шесть минут простоя. Подробности в
`CLAUDE.md`, раздел про доступ к `.env`.

Копия значений после каждой сборки кеша лежит в
`backend/bootstrap/cache/config.php`, тоже `640`. Там те же секреты
открытым текстом — при смене прав не забывать про него.

---

## Сначала — то, что требует действий

**Ключи Selectel утекли в переписку 12.09 и не перевыпущены.**
Это `AWS_ACCESS_KEY_ID` и `AWS_SECRET_ACCESS_KEY` (см. «Объектное
хранилище» ниже). Ключ даёт полный доступ к бакету: чтение, запись и
**удаление** — в том числе резервных копий базы, которые лежат там же,
в префиксе `backups/`.

Что сделать:

1. В кабинете Selectel создать новую пару ключей.
2. Заменить обе строки в `backend/.env`.
3. `php artisan config:cache`, затем `chown root:www-data` и
   `chmod 640` на `bootstrap/cache/config.php` (иначе сайт ляжет —
   разбор в `deploy/docs/vtb-go-live.md`, §4 шаг 4).
4. `systemctl reload php8.3-fpm`.
5. Проверить: `php artisan storage:verify` или загрузка картинки.
6. **Старую пару отозвать в кабинете.** Без этого шага смена
   бессмысленна: утёкший ключ продолжает работать.

Пока не сделано, исходить надо из того, что доступ к хранилищу есть у
всех, кто видел ту переписку.

Отдельно стоит решить: один ключ сейчас и на медиа, и на резервные
копии. Разделить их — значит лишить приложение права удалять копии.
Предложение с числами — в `docs/storage-analysis.md`.

## Сервер

| | |
| --- | --- |
| Что | Боевая машина: приложение, база, очереди, планировщик |
| Адрес | `31.207.75.124`, **SSH на порту 2222**, не 22 |
| ОС | Ubuntu 24.04.5 LTS |
| Доступ | По ключу, вход только root. Пароля нет |
| Где ключ | На машинах разработчика и заказчика, `~/.ssh` |
| Как сменить | Добавить новый публичный ключ в `/root/.ssh/authorized_keys`, проверить вход **вторым окном, не закрывая первое**, затем убрать старый |
| Что сломается | Всё: выкатка, дампы, диагностика. Отдельного пути внутрь нет |

Сменить ключ без второго открытого окна нельзя: ошибка в
`authorized_keys` запирает машину, и останется только консоль хостинга.

| | |
| --- | --- |
| Что | Коды подтверждения телефона |

## Вход через соцсети

| Сервис | Ключи | Что сломается |
| --- | --- | --- |
| Яндекс | `YANDEX_CLIENT_ID`, `YANDEX_CLIENT_SECRET` | Вход через Яндекс; вход по почте остаётся |
| ВКонтакте | `VKONTAKTE_CLIENT_ID`, `VKONTAKTE_CLIENT_SECRET`, `VKONTAKTE_SERVICE_TOKEN` | Вход через ВК |
| MAX | `MAX_BOT_TOKEN`, `MAX_WEBHOOK_SECRET` | Вход через MAX и зеркалирование уведомлений |

Адреса возврата (`*_REDIRECT_URI`) прописаны и в `.env`, и в кабинете
каждого сервиса. Меняются парой, иначе вход отвалится с ошибкой
несовпадения адреса.

## Чего в этом перечне нет

- **Значений.** Ни одного секрета, намеренно.
- **Кабинетов.** Логины в личные кабинеты Selectel, ВТБ, СДЭК, Beget,
  регистратора и GitHub знает заказчик. Здесь их нет и быть не должно.
- **Метрики, Карт и PageSpeed.** Ключи ещё не переданы.
- **Подтверждения, что площадка Selectel в России.** Из настроек видно
  имя региона, а не факт; для 152-ФЗ нужен факт из кабинета.
