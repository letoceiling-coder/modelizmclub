## Находка: раскрытие номера ничем не ограничено

Чек-лист требует «ограничение частоты раскрытия». Его нет.

Восемь запросов подряд по одному объявлению — восемь номеров, ни одного
отказа. За полчаса проб одна учётка сделала **16 раскрытий**, и лимит не
сработал ни разу.

Сегодня собрать почти нечего: номер показывают **2 объявления из 50**,
причём оба принадлежат одному продавцу. Но это свойство данных, а не
защиты. Когда продавцов станет тридцать и половина включит показ номера,
один подписчик выгребет телефоны всего каталога за несколько секунд.

Смягчает то, что след остаётся: раскрытия пишутся в таблицу
`listing_phone_reveals` — 24 записи, 16 из них мои за последние полчаса.
То есть заметить можно, но только задним числом.

Приоритет — **до открытия**, оценка полчаса: отдельный лимитер, как у
расчётов доставки.

## Что проверено и работает

### Номер продавца не утекает в разметку

Главная проверка раздела, и она чистая. Страница объявления, запрошенная
`curl` с `-a`:

```
код 200, 103 016 байт
```

Поиск по разметке нашёл четыре последовательности, похожие на телефоны.
Разобрал каждую:

| Найдено | Что это на самом деле |
| --- | --- |
| `+79898089888` | телефон площадки из подвала, `footer.contacts` |
| `78008291551` | обрывок `…lovable.app-178008291551` — служебное число |
| `79043946196` | обрывок `u:179043946196` из сериализации роутера |
| `79043946201` | то же, для адреса объявления |

**Номер продавца — `+79996300929` — в разметке отсутствует.** В ответе
API его тоже нет: вместо номера отдаётся признак `phone_available`.

Записываю подробно, потому что без разбора четыре «телефона» в HTML
выглядели бы как утечка.

### Расчёт цены размещения — все части на месте

```json
{"base_cents": 3000, "subscriber_adjustment_cents": -1000,
 "price_after_subscription_cents": 2000, "promo_discount_cents": 0,
 "final_cents": 2000, "is_free": false, "free_reason": null,
 "free_listings_remaining": 0, "personal_free_listings_remaining": 0}
```

База 30 ₽, скидка подписчика −10 ₽, итог 20 ₽. Поля под промокод,
бесплатные размещения и личные кредиты присутствуют отдельно — то есть
разбор виден человеку, а не только итог.

Неверный промокод отбивается внятно: `{"code": "NOSUCHCODE", "error":
"Промокод не найден."}`, и форма показывает это и всплывающим
сообщением, и строкой под полем.

**Правка C8 на месте.** Текст «Не удалось рассчитать стоимость
размещения. Попробуйте ещё раз.» живёт в файле переводов, а в
`ads.new.tsx` сохранён разбор: «До 25.09 отказ запроса молча оставлял
`placementQuote` пустым». То есть «0 ₽» вместо отказа больше не
показывается.

### Создание, каталог, мои объявления

- **Валидация называет недостающие поля поимённо**: `title`,
  `description`, `category_id`.
- **«Самовывоз» требует адрес отправки** — отдельная ошибка на
  `pickup_address`.
- **Сортировка работает по всем четырём порядкам.** Цены по возрастанию:
  600 / 700 / 800 ₽; по убыванию: 34 000 / 32 000 / 28 000 ₽.
- **Поиск** по слову «танк» находит 2 объявления.
- **Рейтинг продавца есть в карточке списка** — `rating`,
  `reviews_count`, `is_trusted_seller`. Это правка C5.
- **Счётчик очереди совпадает с базой.** В очереди модератора объявлений
  ноль, и в базе `pending_moderation` тоже ноль. По статусам:
  опубликовано 130, черновиков 7, продано 4, снято 3, отклонено 1.
- **Вложенные категории включаются** — доказано поимённо в части 3.

## Где я остановился и почему

**Публикация упирается в оплату.** Попытка создать объявление с
`publish: true` даёт `422` и «Для публикации объявления нужна оплата». За
этой чертой — настоящие деньги, и дальше я не пошёл.

Из-за этого не проверены три пункта:

- **габариты обязательны при СДЭК** — черновик с `offers_cdek: true` без
  габаритов создаётся (`201`), а проверка, судя по всему, стоит на
  публикации, до которой без оплаты не дойти;
- **оплата до формы банка**;
- **поднятие за 149 ₽**.

Скажите, если платить можно — у учётки приёмки есть кошелёк, и тогда
пройду весь путь.

**Требует экрана** (панель браузера скрыта): галерея во весь экран,
лайтбокс карточки объявления, левое меню не перекрывает фильтры,
4–5 карточек в ряд на 1440.

**Проверено в других частях:** «Написать продавцу» — часть 6, «Купить
через безопасную сделку» — часть 8.

## Заметка о методе

За эту часть я шесть раз чуть не записал ложную находку, и каждый раз
причина была одна: **обращался не тем именем**.

| Искал | Правильно |
| --- | --- |
| `/listings/mine` | `/users/me/listings` |
| `promo_code` | `promocode` |
| текст правки C8 в `.tsx` | он в файле переводов |
| `delivery_methods: ["cdek"]` | СДЭК — отдельный признак `offers_cdek` |
| телефоны регулярным выражением | три из четырёх — служебные числа |
| `category_id` в сообществах (часть 4) | `taxonomy_id` |

Из них два дали бы громкие ложные находки: «мои объявления показывают
чужие 50» и «номер продавца утекает в разметку». Оба сняты разбором
того, что именно нашёл замер.
