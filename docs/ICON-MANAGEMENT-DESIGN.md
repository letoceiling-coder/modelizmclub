## 1. Проблема

На скриншотах видно, что на сайте используются **десятки иконок** в разных местах:

| Место на сайте | Примеры иконок |
|----------------|----------------|
| Главная — карточки разделов | Объявления, Лента, Каналы, Мессенджер, Обзоры (3D-иллюстрации) |
| Главная — «Всё, что движется и летает» | 20 категорий с 3D-иконками |
| Главная — «Почему моделисты выбирают нас» | 4 value-карточки |
| Главная — FAQ | Иконка «+» / «×» в аккордеоне |
| Боковое меню | Лента, Каталог, Избранное, Каналы, Мессенджер… |
| «Найди своих» (лента) | Иконки направлений в списке чатов |
| Шапка / нижняя навигация | Избранное, уведомления, таб-бар |

В админке уже есть **Design System → Иконки**, но администратор не понимает:

1. **Для чего это** — нет связи «страница → иконка → превью того, как выглядит на сайте».
2. **Что уже работает** — слот «Навигация — Лента» меняет иконку только в sidebar/bottom nav, но не везде.
3. **Где менять лендинг** — карточки главной редактируются в **«Главная страница»**, а не в «Иконках».
4. **Нет превью** — «Применить (превью)» меняет иконки «где-то на сайте», но не показывает где именно.

**Цель:** один понятный раздел админки «**Иконки сайта**», где администратор видит **все места** с иконками, текущий вид, может заменить и опубликовать — **дефолты остаются**, пока админ явно не загрузит замену.

## 2. Что уже реализовано (не переписываем)

### Backend ✅

| Компонент | Назначение |
|-----------|------------|
| `icon_assets` | Библиотека загруженных SVG/PNG |
| `system_settings.icon_overrides` | Опубликованная карта `{ slotKey → { svg/url, token } }` |
| `GET /api/v1/icon-overrides` | Публичная выдача для всех пользователей |
| `POST /api/v1/media?purpose=icon` | Загрузка файла |
| `IconAssetService` + `SvgIconSanitizer` | Безопасная обработка SVG |
| Audit log | Откат последней публикации |

### Frontend ✅

| Компонент | Назначение |
|-----------|------------|
| `lib/icon-slots.ts` | Реестр слотов + токены цвета |
| `lib/icon-overrides.ts` | Published map + draft overlay (превью) |
| `components/ui/Icon.tsx` | `<Icon slot="nav.feed" />`, `<CategoryIcon />` |
| `routes/admin.tsx → IconsPanel` | Загрузка, назначение, publish |

### Что уже подключено к слотам

- Sidebar, BottomNav, MobileHeader (burger) — `nav.*`
- RightCategories, FeedRightRail — `category:{id}`
- AdActionPanel — `section.safe-deal`

### Что **не** подключено (дефолты захардкожены)

- DesktopTopBar (избранное, уведомления, мессенджер)
- UserMenu (профиль, мои объявления, подписка)
- FindYourPeopleSheet (мобильный список направлений)
- Landing: values (4 иконки), FAQ (+/×), hero-карточки
- Landing cards — **отдельная система** (`landing_cards.icon` + `icon_url`)
- ~170 файлов с прямым `import from "lucide-react"`

## 3. Архитектурное решение

### Принцип: «Слот = одно видимое место иконки»

```
┌─────────────────────────────────────────────────────────────┐
│  Админ: раздел «Иконки сайта»                               │
│  ┌──────────────┐  ┌──────────────┐  ┌──────────────────┐ │
│  │ Страница/блок│  │ Список слотов│  │ Превью + редактор│ │
│  │ (навигация)  │→ │ nav.feed     │→ │ [текущая][новая] │ │
│  └──────────────┘  └──────────────┘  └──────────────────┘ │
└────────────────────────────┬────────────────────────────────┘
                             │ Publish
                             ▼
              system_settings.icon_overrides (JSON)
                             │
                             ▼
              GET /icon-overrides → все клиенты
                             │
                             ▼
              <Icon slot="nav.feed" /> → override или default Lucide/PNG
```

**Дефолт = то, что сейчас на сайте.** Если в `icon_overrides` нет ключа слота — рендерится `defaultLucide` или `defaultAssetUrl` (для 3D PNG).

**Два типа иконок:**

| Тип | Формат | Перекраска токеном | Пример |
|-----|--------|-------------------|--------|
| **UI-иконка** | Монохромный SVG | ✅ Да | Навигация, FAQ +/- |
| **Иллюстрация** | PNG/WebP (3D) | ❌ Нет | Карточки лендинга, категории |

## 4. Новый UX админки — раздел «Иконки сайта»

### 4.1. Отдельный пункт меню

```

├── Главная страница      ← тексты/карточки лендинга (как сейчас)
```

### 4.2. Навигация «Где на сайте» — дерево страниц

Администратор **не выбирает технический ключ** `nav.feed` из dropdown — он выбирает **понятное место**:

| Группа в дереве | Подпункты | Ключи слотов |
|-----------------|-----------|--------------|
| **Главная страница** | | |
| → Карточки разделов | Объявления, Лента, Каналы, Мессенджер, Обзоры | `landing.card:{slug}` |
| → Блок «Направления» | 3D-печать, Автомодели, … (из API категорий) | `category:{id}` |
| → «Почему мы» | Только моделизм, Живое сообщество, … | `landing.value:{key}` |
| → FAQ | Иконка раскрытия | `ui.faq.expand` |
| **Навигация** | | |
| → Боковое меню | Лента, Каталог, Избранное, … | `nav.*` |
| → Нижняя панель (моб.) | Те же пункты | `nav.*` (общие слоты) |
| → Шапка | Избранное, Уведомления, Мессенджер | `header.*` |
| → Меню пользователя | Профиль, Мои объявления, Подписка | `menu.*` |
| **Лента** | | |
| → «Найди своих» | Заголовок блока + каждое направление | `feed.find-people`, `category:{id}` |
| **Объявления** | Безопасная сделка | `section.safe-deal` |

Поиск по названию: «мессенджер» → находит все слоты с этим словом.

### 4.3. Карточка редактирования слота

Для каждого слота показываем:

1. **Скриншот-контекст** — мини-превью блока (sidebar item, landing card, category tile).
2. **Текущая иконка** — что видят пользователи сейчас (default или override).
3. **Редактор:**
   - Переключатель: «По умолчанию» / «Своя иконка»
   - Загрузка SVG/PNG или выбор из медиа
   - Цвет (токен) — только для SVG, для PNG — подсказка «цвет не меняется»
4. **Кнопки:** «Применить превью» | «Сбросить слот»

### 4.4. Публикация

Без изменений в backend-контракте:

1. **Превью** — draft overlay (`setDraftOverride`) — видит только текущий админ в своём браузере.
2. **Опубликовать для всех** — `PATCH admin/settings` → `icon_overrides`.
3. **Откат** — из audit log (уже есть).

Добавить **счётчик черновиков**: «Изменено 3 иконки (не опубликовано)».

### 4.5. Библиотека иконок

Общая панель «Мои иконки» (загруженные SVG/PNG) — как сейчас, но вынести в боковую колонку или вкладку «Библиотека». Одна иконка может быть назначена на несколько слотов.

## 6. Изменения в данных и API

### 6.1. Без новых таблиц (фаза 1)

Расширяем только `icon_overrides` JSON и реестр слотов. Backend API **не меняется**.

### 6.2. Унификация landing cards (фаза 2, рекомендуется)

Сейчас landing cards хранят `icon` + `icon_url` в `landing_cards`. Два пути:

**Вариант A (минимальный):** «Иконки сайта» для landing показывает карточки read-only из `GET /admin/landing/blocks`, редактирование `icon_url` через существующий API landing — **без слотов**, но в **одном UI-разделе** (вкладка «Главная → Карточки» вызывает тот же `LandingCardIconField`).

**Вариант B (единый):** При publish landing card icon → также пишется в `icon_overrides["landing.card:{slug}"]`. `LandingCardIcon` сначала смотрит override, потом `icon_url` из API.

**Рекомендация:** Вариант A для быстрого UX-win; Вариант B — если нужна единая publish/rollback модель.

### 6.3. Default PNG для категорий (фаза 3, опционально)

```sql
ALTER TABLE post_categories ADD icon_image_url VARCHAR(500) NULL;
```

Seed с текущими 3D-URL. Слот `category:{id}` fallback: override → `icon_image_url` → Lucide `icon`.

```typescript
export interface IconSlot {
  key: string;
  label: string;           // «Боковое меню — Лента»
  group: IconSlotGroup;
  page: IconPage;           // NEW: для дерева в админке
  previewComponent?: string; // NEW: 'SidebarNavItem' | 'LandingCard' | ...
  defaultLucide: string;
  defaultToken: TokenKey;
  defaultAssetUrl?: string;  // NEW: для 3D PNG по умолчанию
  supportsRecolor: boolean;  // NEW: false для PNG-иллюстраций
}

export type IconPage =
  | "landing"
  | "navigation"
  | "feed"
  | "ads"
  | "communities"
  | "channels"
  | "messenger"
  | "global";
```

## 10. Правила для администратора (help-текст в UI)

> **Иконки сайта** — здесь вы меняете картинки в меню, на главной и в блоках направлений.
>
> - **По умолчанию** — стандартные иконки платформы (как при первом запуске).
> - **SVG** — для меню и кнопок; цвет меняется через палитру.
> - **PNG** — для цветных 3D-иллюстраций (карточки, категории); цвет не перекрашивается.
> - **Превью** — только вы видите изменения до нажатия «Опубликовать».
> - **Тексты карточек** главной — в разделе «Главная страница»; **иконки** — здесь.

## 11. Что НЕ входит в scope

| Исключено | Причина |
|-----------|---------|
| Замена всех 170+ Lucide-импортов | Иконки внутри форм, кнопок «Закрыть», chevron в UI-kit — не брендовые |
| Произвольный hex-цвет | Только 9 токенов Design System |
| Редактор SVG в браузере | Загрузка файла достаточно |
| Иконки в admin-панели | Только пользовательская часть |

## 12. Критерии готовности

1. Администратор без документации понимает: зайти в «Иконки сайта» → выбрать «Боковое меню — Лента» → загрузить PNG → увидеть превью → опубликовать.
2. Все места со скриншотов доступны в дереве админки.
3. Сброс слота возвращает **ровно тот** дефолт, что был до любых изменений.
4. Publish/rollback работает через существующий audit log.
5. Пользователи без override видят сайт **идентичный текущему**.

## 13. Связь с текущим Design System

| Было | Станет |
|------|--------|
| Design System → Иконки (технический UI) | **Иконки сайта** — отдельный раздел |
| Design System → Цвета/тема (localStorage) | Design System — только визуальная тема |
