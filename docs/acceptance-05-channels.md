## Что проверено и работает

**Создание через заявку.**

```
POST /channels/apply          → 201, заявка id 16, статус pending
очередь модератора            → заявка там
POST …/applications/16/approve → 200, канал создан, вид «author»
```

Заявка без полей отбивается с указанием недостающего.

**Подписка и счётчик — настоящие.** Не кешированные, меняются сразу:

| Шаг | Подписчиков |
| --- | --- |
| после создания | 0 |
| подписался посторонний | **1** |
| отписался | **0** |

**Публикация только владельцем — доказано правильной причиной.** Это
важнее, чем сам код ответа. Посторонний без подписки получает
`subscription_required` — и по такому отказу нельзя судить о правах, он
сработал раньше. Поэтому проверил модератором: подписка staff не
останавливает, значит отказать должно именно владение.

```
владелец (1276)              → 201, статус published
модератор, не владелец (1207) → 403
   «Публиковать могут владелец и администраторы канала.»
```

То есть посторонний получает 403 **запросом к API**, а не только
спрятанной кнопкой, и по правильной причине.

**Комментарии по галочке владельца — проверка серверная.** Решающая проба
— одно и то же действие одним и тем же посторонним при двух положениях
галочки:

| Галочка | Посторонний комментирует |
| --- | --- |
| включена | **201** |
| выключена | **403** «Недостаточно прав для этого действия» |

Значит выключение действует на сервере, а не только прячет поле ввода.

**Жалоба** отбивается без полей, с полями создаётся (201) и попадает в
очередь модератора; закрывается оттуда же.

**Удаление канала защищено подтверждением названия** — как и у
сообществ.

## Находки

### 1. Владелец комментирует при выключенных комментариях, и счётчик это показывает

При `comments_enabled = false` владелец канала всё же оставил
комментарий, и запись канала стала показывать `комментариев: 1`.

Само по себе исключение для владельца объяснимо. Неудобно другое:
читатель видит на записи счётчик комментариев и сам комментарий, а
ответить не может — поле ввода спрятано, а сервер откажет. Выглядит как
поломка, хотя это правило.

Приоритет — **после запуска**. Либо не показывать счётчик при
выключенных комментариях, либо не пускать и владельца.

### 2. Жалоба принимает неизвестное поле молча, и текст теряется

Отправил жалобу с полем `comment` — сервер ответил `201`, а в записи
`description: null`. Правильное имя поля — `description`; `comment` был
принят и выброшен без единого слова.

Это третий случай того же рода за приёмку: `filter` в ленте,
`category_id` в сообществах, `comment` в жалобах. Неизвестный параметр
нигде не отбивается — он тихо меняет или теряет данные. По отдельности
мелочь, вместе — привычка кода, которая однажды съест что-то важное.

Приоритет — **после запуска**.

## Ложная находка, снятая проверкой

Сначала я получил `201` на комментарий при выключенных комментариях и
уже записал это дефектом — чек-лист прямо требует «403 на сервере».

Ошибка была в том, **чьим токеном** я комментировал: владельца. Решающая
проба — тот же запрос посторонним при двух положениях галочки — показала,
что сервер проверку выполняет, а владелец из неё исключён.

Это четвёртая ложная находка за приёмку, снятая до попадания в отчёт.
Общее у всех: я мерил не тем — не тем узлом, не тем параметром, не тем
токеном.

## Что не проверено

- **Вкладки «Посты» и «О канале»** — проверка экрана, панель браузера
  скрыта.
- **Администраторы канала** («публиковать могут владелец **и
  администраторы**») — нужна вторая учётка с подпиской, чтобы назначить
  её администратором и убедиться, что она публикует. У меня подписка
  одна, и она у владельца.
- **Обложка и аватар канала** — требуют загрузки изображений.
- **Закрепление записи** (`pin`) — в списке чек-листа нет, не трогал.
