# Опись доступов

Все внешние сервисы, от которых зависит сайт: что это, на кого оформлено,
где лежат ключи, как сменить, когда продлевать.

**Самих ключей здесь нет и быть не должно.** Все боевые значения лежат в
одном файле на сервере: `/var/www/modelizmclub/backend/.env`. Он не в
репозитории и не попадает в копии кода.

Состояние на 10.10.2026.

---

## Как читать «на кого оформлено»

Там, где написано **«уточнить»**, я не смог установить это по сайту и по
коду — спросите того, кто заводил. Это не придирка: если сервис оформлен на
бывшего подрядчика, его доступ надо переоформить до того, как он понадобится.

## 4. Приём денег — ВТБ

**Внимание: сейчас указывает на испытательные узлы. Деньги принимать нельзя.**

| Что | Состояние | На кого |
| :-- | :-- | :-- |
| Эквайринг (приём оплаты) | включён, адрес `vtb.rbsuat.com` — **испытательный** | ООО «МОДЕЛИЗМ», ИНН 2312341754 |
| Выплаты продавцам | включены, адреса `epa-ift-sbp.vtb.ru` и `test3.api.vtb.ru` — **испытательные** | то же |
| Ключи | `.env`, группы `VTB_ACQUIRING_*` и `VTB_PAYOUT_*` | |

**Что нужно, чтобы включить деньги:**

1. Получить в ВТБ боевые адреса и ключи для эквайринга и выплат.
2. Вписать их в `.env`.
3. Убедиться штатной проверкой: `check-live-money.sh --require-live` должна
   ответить «боевой», а не «открывать нельзя».
4. Сделать проверочный платёж своей картой на малую сумму с возвратом.

**Почему это важно именно так.** Раньше испытательный адрес подставлялся
сам, молча. Человек видел настоящую форму банка, вводил карту — и ничего не
происходило. Так прошло больше месяца. Теперь адрес без явного указания не
подставляется, а проверка зовётся при каждой выкатке.

| Что | Состояние |
| :-- | :-- |
| ЮKassa | включена, ключ **боевой**. Используется для части сценариев |
| Ключи ЮKassa | `.env`, `YOOKASSA_SHOP_ID` и `YOOKASSA_SECRET_KEY` |

## 5. SMS

| Что | Значение | На кого |
| :-- | :-- | :-- |
| Шлюз | iqsms (он же «СМС Дисконт»), `api.iqsms.ru` | уточнить |
| Ключи | `.env`, `IQSMS_LOGIN` и `IQSMS_PASSWORD` | |
| Имя отправителя | **`SMS DUCKOHT` — не ваше** | |
| Баланс | пополняется в кабинете, **следить** | |

**Согласованное имя отправителя — `MODELIZM`,** и тексты шаблонов для него
утверждены МТС (`docs/sms/mts-approved-templates.md`). Но на проде стоит
iqsms с чужой подписью. Человек получает код подтверждения от незнакомого
отправителя — это снижает доверие и часть людей просто не находит сообщение.

**Как сменить шлюз:** шлюз меняется одним значением `SMS_DRIVER` в `.env`
(`iqsms`, `mts`, `log`) — без выкатки. Нужны ключи нового шлюза.

**Когда кончатся деньги:** человек увидит «Сейчас не получается отправить
код». Это ваш сигнал проверить баланс.

> **Ключ Яндекс ID надо сменить.** Ночью 10.10 при разборе настроек доставки
> я напечатал в рабочий журнал значение `YANDEX_CLIENT_SECRET` — моя ошибка:
> проверка должна была показать «задан / не задан», а показала значение.
> Ключ не утёк наружу и в репозиторий не попал, но считать его закрытым
> больше нельзя. Смена: кабинет Яндекс OAuth → новый секрет → вписать в
> `.env` → пересобрать кеш настроек → перезапустить php-fpm. Старый отозвать.
> Дело пяти минут, и лучше сделать до запуска.

## 9. Что сделать при передаче проекта

По порядку. Первые три — обязательно.

1. **Сменить ключ SSH от сервера.** Кто им владеет, владеет всем.
2. **Сменить пароль базы.**
3. **Сменить `YANDEX_CLIENT_SECRET`** — причина выше.
4. Переоформить на себя: домен, хостинг, Selectel, iqsms, СДЭК, ВТБ.
5. Передать доступ к репозиторию GitHub.
6. Заменить ключи ВТБ и ЮKassa на свои, если юрлицо меняется.
7. Пройти по этому списку и заменить все «уточнить» на имена.

## 10. Что проверять регулярно

| Что | Как часто | Где смотреть |
| :-- | :-- | :-- |
| Баланс SMS-шлюза | раз в неделю | кабинет iqsms |
| Место на диске сервера | раз в неделю | сторож пишет сам при нехватке |
| Копии базы делаются | раз в месяц | `/root/backups/auto/` |
| Сертификаты HTTPS продлились | раз в месяц | в браузере — замок в адресе |
| Уязвимости в зависимостях | раз в месяц | GitHub → Security → Dependabot |
| Список сотрудников | раз в месяц | Админка → Пользователи, роль ≠ «Пользователь» |

Последнее — самое недооценённое. Роль, выданная «посмотреть», живёт
месяцами. Список сотрудников короткий, и он должен целиком объясняться
словами.
