## Находки

### 1. Справочник категорий сообществ и сами сообщества — разные списки

При создании сообщества и в фильтре предлагается восемь категорий:

```
Авиация · Авто · Автопилоты для кораблей · Гусеничная техника
Корабли · Монеты · Роботы · Рыбалка
```

А у восемнадцати существующих сообществ стоят совсем другие:

```
По масштабу (4) · 1/35 (2) · По тематике (2) · Официальные сообщества
1/72 · 1/48 · 1/32 · 1/16 · Историческая · Фэнтези · Sci-Fi
Железные дороги · Региональные клубы
```

**Пересечение пусто. Ноль из восемнадцати** сообществ относится хоть к
одной из предлагаемых категорий.

Первый список — названия направлений, второй — способ группировки самих
сообществ. Человек, выбравший в фильтре «Авиация», не найдёт ничего, а
создавший сообщество в «Авиации» окажется единственным в своей
категории — я это и получил, заведя пробное: у него категория «Авиация»,
и похожих к нему **ноль**, потому что других в ней нет.

То есть и фильтр по категории, и подбор похожих работают правильно — их
подвели данные.

Приоритет — **до открытия**. Оценка: разговор плюс час. Решить, какой из
двух списков верный, и привести второй к нему.

### 2. Писать на стену сообщества может только подписчик

Участник с подтверждённым телефоном, но без подписки получает при
публикации:

```
403 subscription_required — «Оформите подписку, чтобы публиковать контент»
```

Это согласуется с матрицей из части 1 и, скорее всего, задумано. Но в
сообществе это значит, что вступить может любой, а написать — только
подписчик. Стоит убедиться, что это ваше решение, а не побочное
следствие общего правила на публикации.

### 3. `category_id` в списке сообществ отдаёт посторонние

Запрос `/communities?category_id=<любой>` возвращает одни и те же
четыре сообщества, все категории «По масштабу» — проверено на четырёх
разных значениях. Работающий параметр называется `taxonomy_id`, и
интерфейс шлёт именно его, так что через кнопки это не воспроизводится.

Тот же класс, что находка с фильтром ленты в части 2: неизвестный или
чужой параметр не отбивается, а тихо меняет выдачу.

Приоритет — **после запуска**, полчаса.

## Что проверено и работает

**Полный круг создания — заявка, очередь, одобрение.**

```
POST /communities/apply     → 201, заявка id 27, статус pending
GET  /me/entity-requests    → заявка видна автору
очередь модератора          → заявка там, с именем автора и категорией
POST …/applications/27/approve → 200, сообщество создано
GET  /me/entity-requests    → статус у автора стал «approved»
```

Заявка попадает **в общую очередь модерации** вместе с заявками на
каналы — как и задумано.

**Вступление и выход.** Счётчик и признак участия меняются согласованно:
9 → 8 при выходе, 8 → 9 при возврате, `is_member` переключается вместе с
числом. Повторное вступление не удваивает участие.

**Запись на стене.** Создание отдаёт черновик, публикует отдельный вызов
— это намеренно и описано в коде: «createPost заводит только черновик,
иначе в воронку попадали бы брошенные наброски». Чуть не записал в
дефекты, пока не прочитал.

**Владелец публикует сразу при любом положении переключателя.** Проверил
оба: с `moderate_member_posts` включённым и выключенным запись владельца
получает статус `published` немедленно.

**Мероприятия — весь список.**

| Шаг | Результат |
| --- | --- |
| создание без полей | 422, названы оба недостающих поля |
| создание | 201, статус `published` |
| «Пойду» участником | 200, участник появился в списке идущих |
| напоминание владельцем | 200, «Напоминание отправлено отметившимся» |
| повторное напоминание | 422, «уже отправлено недавно», указан `next_at` |
| отмена | 200, статус `cancelled` |
| удаление | 200 |

Защита от повторного напоминания работает и называет время следующего —
это правка C7.

**Участники.** Список отдаётся, исключение работает: 2 → 1.

**Чат сообщества виден в мессенджере.** Мессенджер запрашивает диалоги
тремя вызовами с параметром `space`; при `space=communities` чат
«ModelizmClub» на месте, при `space=rooms` — чат направления «Планеры».

**Удаление сообщества защищено подтверждением.** Требуется ввести точное
название: неверное даёт 422 «Введите точное название сообщества для
подтверждения». Хорошая защита, сработала.

учётка с подпиской. У меня подписка одна, и она у владельца сообщества, а

единственный пункт раздела, который не закрыт по существу.

**Обложка, аватар, описание** — требуют загрузки изображений.

**Предложка** — по вашему же чек-листу известно, что не работает; не
трогал.

**Меню «Ещё» (восемь пунктов), поиск по участникам, назначение
управляющих, фильтры в интерфейсе** — это проверки экрана, а панель
браузера скрыта.
