# Яндекс.Метрика: что задаётся не кодом

Счётчик подключается из `frontend/src/lib/analytics/metrika.ts`. Почти всё
там — код, который едет с веткой. Три вещи кодом не управляются, и если их
не сделать, счётчик либо молчит, либо пишет лишнее.

## 1. Номер счётчика

Без него модуль не делает ничего: `isMetrikaConfigured()` отвечает «нет»,
загрузка молча выходит. Это штатный режим разработки — Вебвизор не должен
писать локальные сессии, — но на проде выглядит так же, как поломка:
выкатка проходит зелёной, а отчёты остаются пустыми.

Номер приезжает в сборку переменной окружения. Сборка идёт в отдельном
рабочем дереве (`git worktree add --detach` в `deploy-frontend.sh`), поэтому
неотслеживаемый `frontend/.env` в неё не попадает — класть номер туда
бесполезно.

```bash
# на сервере, в backend/.env
METRIKA_ID=00000000
```

`deploy-frontend.sh` читает эту строку и экспортирует `VITE_METRIKA_ID`.
Если номера нет, скрипт печатает предупреждение и собирает фронт без
счётчика — это не отказ выкатки.

## 2. «Записывать содержимое полей» — выключить

Настройка счётчика в кабинете Метрики, раздел Вебвизора.

Код помечает поля ввода классом `ym-disable-keys`, а переписку — классом
`ym-hide-content` (`markPrivate`, наблюдатель за деревом). Разметка
закрывает **ввод**: то, что человек набирает. Предзаполненное значение —
подставленный телефон, сохранённый адрес, значение из автозаполнения
браузера — закрывает только эта галочка.

Параметра «маскировать по селектору» у Метрики нет. До 22.09 в коде стоял
`params: { maskSelector: … }`; `params` в `init` — это параметры визита, то
есть селектор уезжал в отчёты как произвольные данные и не маскировал
ничего. Если увидите похожее снова — это не настройка.

## 3. Цели заводятся в кабинете

Имена берутся из `GOALS` в `metrika.ts` и сопоставляются строкой. Цель, не
заведённая в кабинете, в отчётах не появится, и ошибка будет молчаливой —
`reachGoal` с неизвестным именем не жалуется.

| Имя в кабинете | Когда срабатывает |
| --- | --- |
| `signup` | подтверждена почта кодом, либо вход через VK/Яндекс/MAX завёл учётку |
| `phone_verified` | телефон подтверждён кодом |
| `post_published` | запись опубликована (не создана — создание заводит черновик) |
| `listing_published` | объявление размещено |
| `deal_created` | безопасная сделка создана |
| `subscribed` | подписка стала активной (не возврат с формы банка) |
| `community_joined` | человек стал участником (не подал заявку) |

Считается событие, а не человек: повторная публикация из архива, смена
номера, повторное вступление дают цель заново. Уникальных людей Метрика
считает сама, отдельным показателем в отчёте по цели.

Публикация считается по действию человека, а не по решению модератора:
`listing_published` срабатывает и когда объявление ушло на проверку.
Воронка меряет, сколько людей дошли до конца формы; сколько из них прошли
модерацию — видно в самой модерации.

## Как убедиться, что всё работает

1. `curl -s https://modelizmclub.ru/ | grep -c mc.yandex` — должно быть
   **ноль**: до согласия на cookie к Яндексу не уходит ни одного запроса.
2. В браузере принять cookie, затем в консоли `window.ym` — функция есть,
   в сети виден `tag.js`.
3. Перейти на другую страницу без перезагрузки — в сети новый `watch`.
   Просмотр считается по смене пути; правка параметров запроса
   (`?chat=…`, фильтры каталога) просмотра не даёт намеренно.
4. Открыть запись Вебвизора и проверить поле пароля на `/login`: ввод
   должен быть закрыт. Если виден — см. пункт 2 выше, галочка в кабинете.
