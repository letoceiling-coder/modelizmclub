# Подкатегории направлений и тестовые объявления

Согласовано с заказчиком 12.09. Две команды, обе с `--dry-run` и с проверкой
результата отдельными запросами по факту в таблицах.

## Подкатегории — `categories:add-subcategories`

Список узлов — в самой команде (`AddDirectionSubcategoriesCommand::PLAN`):
38 новых узлов, из них 6 третьего уровня. Узел заводится тем же путём, что в
админке: строка в `post_categories`, затем зеркало в каталог объявлений и в
категории сообществ через `CategoryTaxonomyService::syncFromPostCategory`.

```bash
php artisan categories:add-subcategories --dry-run   # план и все записи в зеркала
php artisan categories:add-subcategories             # запись и проверка
```

- Направление, у которого нет ни одного зеркала, синхронизируется целиком,
  вместе с уже заведёнными подкатегориями. У отражённого (Авиация,
  Бронетехника, Рыбалка) — только новые узлы: полная синхронизация
  перевесила бы существующие зеркала («ил 6» в каталоге висит под Авиацией,
  а в дереве направлений — под Планерами).
- Запись в зеркало, которая заняла бы чужую строку с тем же slug, —
  конфликт: команда останавливается до записи.
- Без подкатегорий остаются Kotello, АкваРобот и Каналы.
- Цены размещения у новых категорий каталога не заданы — действует цена
  родителя или общая.

## Демо-набор — `listings:demo`

Команда выросла из «тестовых объявлений» в весь демонстрационный набор:
люди, дружба, записи ленты, сообщества, каналы, переписка, объявления и
добор полноты по дереву направлений. Механизм один, пометка одна, удаление
одной командой.

```bash
php artisan listings:demo --dry-run                  # план по всем разделам
php artisan listings:demo                            # создать всё и проверить
php artisan listings:demo --section=users --section=posts   # только эти разделы
php artisan listings:demo --only=armor-spg,armor-rc  # только объявления в этих узлах
php artisan listings:demo --batch=25 --pause=2       # порциями с паузой
php artisan listings:demo --purge --dry-run          # что будет удалено
php artisan listings:demo --purge                    # удалить всё
php artisan listings:demo --purge --force            # удалить, даже если внутри есть чужое
```

**Разделы и порядок.** `users → friends → posts → communities → channels →
chats → listings → coverage`. Порядок жёсткий: следующий опирается на
созданное предыдущим. `--section` можно называть в любом порядке — команда
всё равно отсортирует, иначе «chats,users» завёл бы переписку между
несуществующими людьми.

**`--only` означает только объявления.** Вызов с `--only` работает ровно
как раньше и остальных разделов не трогает.

**Порциями, а не разом.** Каждая картинка проходит конвейер медиа: четыре
размера в трёх форматах. `--batch` задаёт, сколько единиц идёт подряд,
`--pause` — паузу между порциями. На проде запускать с паузой: это те же
ядра, на которых сервер отвечает живым людям.

### Ограничения, которые стоит знать заранее

- **Участников в сообществе не больше, чем демо-людей.** В задании была
  «полусотня», но людей 36, а набирать живых нельзя. Верх — 34.
- **Записей на вариант — пять, а не «пять–восемь».** Восемь на каждый из
  десяти вариантов дало бы 80 записей только на фотографии, а общий потолок
  — 80 на весь набор.
- **Телефоны выдуманы**, блок `+7 999 900 00 XX`. Смс им никто не шлёт:
  подтверждение ставится полем, минуя отправку кода.
- **Видео собирается ffmpeg.** Если его нет, записи создаются без видео, и
  команда об этом предупреждает.
- **Подписка без администратора не выдаётся.** Признак доступа —
  `granted_by_admin_id`; без него строка в таблице есть, а доступ закрыт.
  Команда предупреждает, если администратора нет.

**Пометка.** Продавцы — `seller1…seller4@demo.modelizmclub.ru`; по домену
объявления находятся и удаляются. Первая строка каждого описания —
«Тестовое объявление — не продаётся.»: лоты публичные, и покупатель должен
видеть, что покупать нечего.

**Что создаётся.** 2–3 лота на узел (`App\Support\DemoListingCatalog`), две
картинки-заглушки на лот (`DemoImageFactory`: цветной фон и подпись), город
из первых 25, доставка «Почта России» и «Самовывоз». Объявление создаётся
`ListingService::create` с `taxonomy_id` узла — черновиком, без оплаты
размещения, — и публикуется `markPublished`, как при одобрении модерацией.
Платежей не появляется.

**Где объявлений нет.** Выставки и события, Обзоры наборов, Техники и
мастер-классы, Каналы, Kotello, АкваРобот, Рыбалка → Трофеи и Водоёмы —
продавать там нечего. «ил 6» — объявление перевесило бы его зеркало в
каталоге, а узел оставлен как есть.

**Удаление.** `--purge` удаляет всех людей на домене
`demo.modelizmclub.ru` через `UserFullDeletionService` (тем же, что
`user:purge`). Каскадом уходят их объявления, записи, комментарии,
реакции, а также каналы, где демо-человек владелец, и сообщества, где он
создатель. Личные диалоги, в которых обе стороны демо, удаляются отдельно:
без этого осталась бы пустая строка в списке бесед.

Две защиты:

1. **Безопасные сделки.** Если по демо-объявлению есть сделка, команда
   отказывается всегда — там деньги живого покупателя. `--force` этого не
   отменяет.
2. **Чужое внутри демо-данных.** Живой человек мог вступить в демо-сообщество,
   написать на стену, подписаться на демо-канал или прокомментировать
   демо-запись. Команда считает такое и по умолчанию отказывается, напечатав,
   что именно нашла. Продолжить можно `--force` — осознанно.

Файлы картинок в хранилище остаются — как при любом полном удалении
пользователя.
