# Восстановление базы из резервной копии

Процедура и журнал учений. Записано 10.09.2026, после первого учения с
проверкой содержимого.

## Зачем этот документ

До него восстановление выглядело непроверенным. Скрипт `restore-db.sh`
существовал с 04.09, но нигде не было ни отметки о запуске, ни
длительности, ни того, что после восстановления сверяли. Аудит 10.09 так и
записал — «не проверялось ни разу», — и ошибся: следы трёх прогонов лежали
в `/root/backups/auto/pre-restore/` (05.09, 07.09, 08.09), просто их никто
не искал, потому что искать было негде.

Отсюда правило: **у учения должен остаться письменный след**, иначе через
неделю оно неотличимо от несделанного. Журнал — в конце файла.

## Процедура

Восстановление — единственная операция здесь, которая уничтожает данные.
Поэтому:

**Никогда не восстанавливайте в боевую базу «чтобы проверить».** Учение
идёт в отдельную базу, боевая не участвует.

```bash
# 1. Учебная база (владелец тот же, иначе pg_restore упрётся в права)
sudo -u postgres createdb -O modelizmclub modelizmclub_restore_drill
sudo -u postgres psql -d modelizmclub_restore_drill \
  -c "GRANT ALL ON SCHEMA public TO modelizmclub;"

# 2. Свежий суточный дамп
DUMP=$(ls -t /root/backups/auto/daily/*.dump | head -1)

# 3. Восстановление с замером
cd /var/www/modelizmclub
time bash deploy/scripts/restore-db.sh "$DUMP" \
  --database modelizmclub_restore_drill --yes

# 4. Уборка
sudo -u postgres dropdb modelizmclub_restore_drill
rm -f /root/backups/auto/pre-restore/*restore_drill-before-restore.dump
```

`--database` обязателен: без него цель берётся из `backend/.env`, а там
боевая база. `--yes` пропускает только вопрос, но не страховочный дамп —
его скрипт делает всегда и отказывается работать, если дамп не удался.

Страховочный дамп при учении — это дамп **пустой учебной базы**, около
килобайта. Не путайте его с копией боевых данных.

## Чего мало для «восстановление работает»

Сообщение `restore OK: … now has 142 tables` говорит только о каркасе.
Таблицы могут быть пустыми, и всё равно будет «OK». Проверяйте содержимое:

```bash
# число строк по ключевым таблицам — боевая против копии
for t in users posts listings safe_deals payments wallet_transactions messages; do
  a=$(sudo -u postgres psql -d modelizmclub              -tAc "SELECT count(*) FROM $t")
  b=$(sudo -u postgres psql -d modelizmclub_restore_drill -tAc "SELECT count(*) FROM $t")
  printf '%-22s боевая %-7s копия %-7s %s\n' "$t" "$a" "$b" \
    "$([ "$a" = "$b" ] && echo совпало || echo РАСХОЖДЕНИЕ)"
done

# и содержимое, а не только счёт
sudo -u postgres psql -d modelizmclub_restore_drill -tAc \
  "SELECT md5(string_agg(email, ',' ORDER BY id)) FROM users"
```

**Расхождения ожидаемы и должны объясняться, а не игнорироваться.** Дамп
снят в момент времени; всё, что появилось позже, в копии отсутствует. В
учении 10.09 разошлась ровно одна строка — беседа №96, созданная через два
часа после снятия дампа. Если расхождение объяснить нечем, это уже не
особенность, а находка.

Про часовой пояс при сверке дат: колонки времени объявлены `timestamp
without time zone` и хранят московское время, а имя дампа и `date -r` —
UTC. Разница три часа, и она делает «созданo раньше дампа» похожим на
«созданo позже». См. CLAUDE.md, раздел про возраст строки в SQL.

## Если восстанавливать придётся всерьёз

Тогда цель — боевая база, и порядок другой:

1. Снять свежий дамп прямо сейчас: `bash deploy/scripts/backup-db.sh --pre-deploy`.
2. Погасить запись: остановить планировщик
   (`systemctl stop modelizmclub-scheduler.timer`), иначе фоновые команды
   будут писать в базу во время восстановления.
3. `bash deploy/scripts/restore-db.sh <дамп>` — **без** `--yes`, чтобы
   вручную подтвердить имя базы.
4. При неудаче скрипт печатает готовую команду отката на страховочный
   дамп. Она и есть план Б.
5. Поднять планировщик, прогнать `deploy/scripts/smoke-check.sh`.

Кеш конфигурации при этом не трогать: `config:clear` от `www-data` кладёт
приложение в sqlite. См. CLAUDE.md, раздел про доступ к `.env`.

### Учение 10.09.2026 подробно

Дамп суточный, снят автоматическим таймером в 04:02 UTC. Восстановление в
учебную базу заняло **две секунды**, копия заняла 22 МБ, таблиц 142 —
столько же, сколько в боевой.

Сверка строк по двенадцати таблицам: **одиннадцать совпали точно**,
одна разошлась на единицу и объяснена (беседа, созданная после снятия
дампа).

| Таблица | Боевая | Копия |
| --- | ---: | ---: |
| users | 17 | 17 |
| posts | 70 | 70 |
| listings | 33 | 33 |
| safe_deals | 27 | 27 |
| payments | 107 | 107 |
| wallet_transactions | 42 | 42 |
| messages | 302 | 302 |
| communities | 5 | 5 |
| post_categories | 41 | 41 |
| feedback | 5 | 5 |
| migrations | 92 | 92 |
| conversations | 94 | 93 |

Содержимое сверялось не счётом, а значениями: совпали контрольные суммы
списка адресов пользователей, списка идентификаторов объявлений и списка
заголовков записей, а также суммы по кошельку и по платежам. То есть
восстановились именно данные, а не пустой каркас нужной формы.

Учебная база и её страховочный дамп удалены сразу после сверки. Боевая
база не участвовала.
