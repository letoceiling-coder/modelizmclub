## 1. Блокирует запуск: деньги идут в испытательный контур

Самое важное. Приём денег **включён**, учётные данные заданы, но все три
денежных пути указывают на испытательные узлы ВТБ. Человек видит форму
банка, вводит карту — и платёж не списывается.

| контур | куда указывает | состояние |
| --- | --- | --- |
| Эквайринг | `https://vtb.rbsuat.com/payment/rest/` | **испытательный** |
| Выплаты, вход | `https://epa-ift-sbp.vtb.ru/passport/oauth2/token` | **испытательный** |
| Выплаты, API | `https://test3.api.vtb.ru:8443/openapi/smb/efcp` | **испытательный** |
| Безопасная сделка | держится тем же эквайрингом | наследует испытательный |

**Что сделать.** Получить боевые адреса и доступы ВТБ, вписать в
`backend/.env`, пересобрать кеш конфигурации, перезагрузить php-fpm. Затем
обязательно:

```bash
bash deploy/scripts/check-live-money.sh --require-live
```

Ответов три, путать нельзя: `0` боевой, `1` испытательный, `2` — выяснить не
удалось. Последнее не «всё хорошо».

Порядок выкатки расписан в `deploy/docs/vtb-go-live.md`.

## 2. Безопасность: срочнее запуска

### 2.1 Ключи хранилища утекли 12.09 и действуют

Та же пара ключей даёт и картинки, и **полные ночные копии базы** — они
уходят в тот же контейнер `knowledge-raw` каждую ночь в 04:00. С 12 сентября
туда ушло больше двадцати копий со всеми персональными данными.

Перевыпустить и **отозвать старую пару**. Без второго шага первый
бессмыслен. Разбор для юриста — `BACKUP-LEAK.md`.

### 2.2 Копии базы лежат рядом с картинками

Отдельный контейнер и отдельный ключ: у приложения должно быть право класть
картинки и не быть права читать и удалять резервные копии.

### 2.3 Доступ к серверу не только ваш

- Три из пяти ключей входа — не ваши. Два из них не использовались ни разу
  за месяц журналов, третий принадлежит ушедшему разработчику (114 входов,
  последний 02.10).
- **Вход root по паролю разрешён**, на портах 22 и 2222. 17 586 неудачных
  попыток подбора в журнале. Паролем за месяц не вошёл никто — значит
  запретить его безопасно.
- `/root/.ssh/id_ed25519` представляется GitHub как учётная запись ушедшего
  разработчика.

Порядок важен: сначала закрыть вход по паролю, потом убедиться в своём
ключе, и только потом убирать чужие. Иначе легко отрезать себя от сервера.

### 2.4 Владельцы площадки — посторонние

| id | роль | кто |
| --- | --- | --- |
| 508 | **Владелец** | `dsc-23@yandex.ru` — приставка совпадает с ключом ушедшего разработчика |
| 1204 | **Владелец** | вход через VK, последний раз 19.07 |
| 1205 | модератор | **вы** |

Выдать себе Владельца, снять роль с 508 и 1204, отозвать их сессии.

```bash
ssh root@modelizmclub.ru "sudo -u postgres psql -d modelizmclub -c \"update users set role='owner', updated_at=now() where id=1205;\""
```

После — выйти и войти заново: роль живёт в токене.

## 3. Не настроено

### 3.1 Яндекс.Карты и Метрика

Настройки `integrations.keys` в базе **нет вовсе**. Проверено на живой
странице: ноль запросов к Яндексу, `window.ym` не определён — счётчик не
работает, карта не на чём рисоваться.

Заводится без выкатки: админка → настройки → ключ `integrations.keys`:

```json
{ "yandex_maps_key": "…", "metrika_id": "…" }
```

### 3.2 Видео для «Как пользоваться»

Страница наполнена, девять разделов на месте, разметка для видео правильная
и мобильная (`playsInline`, ширина по экрану, 16:9). Поле пустое — нужен
файл. Загружается в «Правовых страницах», это раздел уровня Владельца.
