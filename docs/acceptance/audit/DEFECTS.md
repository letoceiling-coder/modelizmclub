**P2** — исправить в первую неделю; **P3** — наблюдение.

Коммит проверки: `75fb23a7` (master). Ширины и роли указаны в каждой

## Исправлено в ветке `front-final/2026-10-05`, ждёт слияния

Это не отдельные дефекты к починке, а перечень того, чем master хуже
готовой ветки. Слияние (PR #16) закрывает всё перечисленное.

### A-01 · P1 · Поисковики не видят, что на странице

**Где.** `master`, все карточки: `/ads/{uuid}`, `/channel/{slug}`,
`/communities/{slug}`, `/user/{uuid}`, `/reviews/{uuid}`.
**Роль.** гость. **Ширина.** не зависит.

**Шаги.** `curl -s http://стенд/ads/22e3df81-… | grep -ao '<title>[^<]*'`

**Ожидание.** Заголовок страницы — название объявления.
**Факт на master.** «Объявление — МоДелизМ» у всех объявлений, «Канал —
МоДелизМ» у всех каналов, «Профиль — МоДелизМ» у всех людей. Описание —
общий текст про площадку. `og:title` — имя площадки.

Следствие: любая ссылка в мессенджере выглядит одинаково.

**Снимок.** Повторяется той же командой.
**Закрыто.** Коммит `146845c0` в ветке.

## Найдено этим аудитом

### B-01 · P1 · Полки каталога не связаны с направлениями

**Где.** Данные, не код. Проверено на стенде; на проде проверить
запросом.
**Роль.** продавец.

**Шаги.**
```sql
select count(*) as всего, count(listing_category_id) as с_полкой
from post_categories where in_listings = true;
```

**Ожидание.** Числа равны: у каждого направления, помеченного «в
объявлениях», есть полка каталога.
**Факт на стенде.** 30 и 0. Следствие — `/categories/listings` отдаёт
ноль узлов, отбор каталога по разделу пуст, мастер объявления не
проходится дальше второго шага.

Полка необязательна по устройству (у «Мастерской» и «Выставок» её нет и
не предполагается), поэтому это не дефект кода — но при нуле связей
раздел объявлений нерабочий.

**Снимок.** Запрос выше.

### B-02 · P3 · CSP работает в режиме наблюдения, не блокирует

**Где.** `deploy/nginx/modelizmclub.ru.conf`, строка 79.
**Факт.** Заголовок `Content-Security-Policy-Report-Only`. Нарушения
собираются (`/csp-report`, команда `csp:violations`), но не
пресекаются.

Это осознанный поэтапный ввод, а не ошибка. До запуска — решение
владельца: переводить в блокирующий или нет.

### B-03 · P3 · Политика CSP разрешает хранилище чужого прототипа

**Где.** та же строка: `img-src` и `media-src` и `connect-src`
содержат `https://pub-bb2e103a32db4e198524a2e9ed8f35b4.r2.dev`.
**Факт.** После слияния ветки (A-05) картинки оттуда больше не
запрашиваются, и разрешение можно убрать.

### B-04 · P3 · Аватары зависят от стороннего сервиса

**Где.** У всех, кто не поставил свою фотографию, аватар —
`https://api.dicebear.com/7.x/initials/svg?seed=…`.
**Факт.** Внешняя зависимость: если сервис недоступен, аватары не
рисуются. Разрешён в CSP.

Отдельно: такой SVG не годится в превью соцсетей — ни один мессенджер
его не рисует. В ветке он из `og:image` исключён (`146845c0`).

### B-05 · P3 · Недоступное хранилище отдаёт 500 с трассировкой

**Где.** `/api/v1/media/{uuid}/medium.webp`.
**Шаги.** Запросить медиа, лежащее на диске `s3`, при недоступном S3.
**Факт.** `League\Flysystem\UnableToCheckFileExistence` → 500, и при
`APP_DEBUG=true` наружу уходит трассировка с путями.

На проде `APP_DEBUG` обязан быть false (пункт 1.1 чек-листа), тогда
трассировки не будет; но код ответа останется 500 вместо 502/404.

**Оговорка.** Это измерено на стенде, где S3 недоступен по политике
сети. Доказательством неисправности прода не является.

### B-06 · P3 · Посторонние поля в запросе правки профиля дают 200

**Шаги.**
```
PATCH /api/v1/users/me  {"role":"owner","is_subscriber":true}
```
**Ожидание.** 422 либо игнор с понятным ответом.
**Факт.** 200. Повышения **не происходит** — роль осталась `user`,
`updated_at` не изменился, то есть строка не тронута. Поля отброшены
до изменения.

Не уязвимость; замечание о строгости разбора запроса.

### B-07 · P3 · Каталог vendor весит 4,9 ГБ

**Факт.** `backend/vendor` — 4,9 ГБ, из них `sebastian` 1,8 ГБ,
`phpunit` 999 МБ. Для Laravel это ненормально много и замедляет любую
выкатку и сборку образа.

Проверить на проде: там ставится `composer install --no-dev`, и этих
двух каталогов быть не должно.
