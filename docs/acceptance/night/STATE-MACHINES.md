# Переходы безопасной сделки — по фактическому коду

Снято 04.10.2026 чтением `app/Modules/Billing/Services/SafeDealService.php`
на коммите ночной ветки. Статусы — `app/Enums/SafeDealStatus.php`.
Названия статусов **не переименовывались** (прямой запрет NIGHT-RUN).

Восемь статусов: `created`, `paid`, `shipped`, `delivered`, `completed`,
`disputed`, `refunded`, `cancelled`.

### Чего в таблице нет намеренно

- Перехода из `completed`, `refunded`, `cancelled` — это финальные
  состояния, выходов из них в коде нет.
- Перехода «продавец подтверждает получение» — его нет и быть не должно
  (R2). Отказ продавцу и постороннему закрыт политикой
  (`Policies/SafeDealPolicyTest`).
- Автоматического возврата по просрочке отгрузки — его нет. Это DEC-04,
  решения владельца нет, и отсутствие автоматики здесь безопаснее её
  наличия.

## `completed` и `released`

В Библии v2.0 финальный статус назван `released`, в коде его нет:
выплата продавцу — это переход в `completed`, а слово «release» живёт
в названии механизма (`autoRelease`, `SAFE_DEAL_AUTO_RELEASE_DAYS`) и в
полях платёжного контура, но не в статусе сделки.

Соответствие: **`released` из документа = `completed` в коде.** Статус не
переименовывается; расхождение записано здесь и в `BIBLE-DIFF.md`.

## Граница срока открытия спора

`SafeDealService::openDispute`, строка 606:

```php
if ($deal->hold_expires_at !== null && ! $deal->hold_expires_at->isFuture()) {
    throw ValidationException::withMessages(['deal' => ['Срок для открытия спора истёк.']]);
}
```

То есть **ровно в секунду истечения спор уже закрыт**, и это совпадает с
решением на ночь (DEC-08). Проверки на границу не было — `hold_expires_at`
упоминался в тестах один раз, и только чтобы убедиться, что поле отдаётся
наружу.

Закреплено `tests/Feature/DisputeDeadlineIsExactTest.php`, четыре точки:

| Точка | Ожидание | Факт |
| :-- | :-- | :-- |
| за секунду до срока | спор открывается | 201 |
| **ровно в секунду истечения** | спор закрыт | 422, «Срок для открытия спора истёк.» |
| через секунду после срока | спор закрыт | 422 |
| срок не задан (`null`) | спор открывается | 201 |

Три точки, а не одна, потому что проверка «за секунду до истечения спор
открывается» зеленеет и при нестрогом сравнении — то есть ничего не
доказывает. Четвёртая точка (`null`) стоит против перебора в ужесточении:
отсутствие срока — это «окно открыто», а не «срок истёк».

Доказательство откатом: смягчение границы до
`isAfter(now()->subSecond())` краснит ровно проверку границы
(`Tests: 4, Failures: 1`).

## Режим захвата и тексты про заморозку

Фактический режим в ночном контуре — заглушка: `check-live-money.sh`
отвечает кодом 1, провайдер `stub`, адреса ВТБ не заданы. Банка в контуре
нет (R6), поэтому банковская часть цикла — `BLOCKED`, логика проверена
на подставном провайдере и помечена **«не банк»**
(`ThreeOutcomesOnStubContourTest`).

Тексты, обещающие заморозку денег, сторожит отдельная проверка
`SafeDealHoldWordingTest` — она в зелёном прогоне. Подпись про срок
в коде намеренно говорит о сроке, а не о холде (комментарий на строке
603): срок есть в обоих режимах, а холд — только в двухстадийном.
