## Зависимости: что именно и почему не обновлял

### Бэкенд: четыре записи, все про Laravel 11.54.0

| Важность | Что | Исправлено в |
| :-- | :-- | :-- |
| high | CRLF injection в стандартном правиле `email` (CVE-2026-48019) | `<12.60.0` |
| medium | Temporary Signed URL Path Confusion | `<12.61.1` |
| low / без CVE | ещё две записи того же ряда | `<12.69.0` и `<13.30.0` |

**Ни одной из них нельзя закрыть патч-версией.** Все исправления
начинаются с Laravel 12, то есть требуют мажорного обновления, а
NIGHT-RUN разрешает только патч-версии (промпт 13, шаг 10) и прямо
запрещает мажорные (2.5.8). `docs/BIBLE.md` VII.5 относит переход
11 → 12 к тому, что можно делать при живых людях.

**Главная из них — CRLF в правиле `email` — в приложении уже обойдена.**
В проекте есть собственное правило `App\Rules\SafeEmail`, и за тем,
чтобы оно стояло **везде**, следит отдельная проверка
`SafeEmailRuleEverywhereTest`. У самого сторожа была история: ревью
нашло у него три прохода (правила строкой через `|`, поле без слова
`email` в имени, вложенные скобки), и все три закрыты коммитом
`chore/laravel-security-patch`. Плюс `EmailCrlfValidationTest` и
`Unit/SafeEmailTest`.

То есть утверждение `docs/BIBLE.md` VII.5 «ни одна уязвимость не
достижима» для этой записи подтверждается кодом, а не надеждой.

### Фронтенд: 37 записей, все в сборочной цепочке

Разобрал каждую по пути зависимости. **Ни одна не попадает в то, что
исполняется у пользователя в браузере:**

| Пакет | Откуда тянется | Когда работает |
| :-- | :-- | :-- |
| `brace-expansion` (12 записей) | `eslint`, `typescript-eslint`, `workbox-build` | линтер и сборка |
| `vite` (2) | прямая зависимость разработки | сборка и локальный сервер |
| `postcss`, `postcss-selector-parser`, `nanoid` | `vite`, `tailwindcss` | сборка стилей |
| `@babel/core`, `browserslist`, `baseline-browser-mapping` | плагины роутера и React, `workbox-build` | сборка |
| `fast-uri` | `ajv` из `eslint` и `@hookform/resolvers` | линтер и разбор схем |

`nanoid` стоит отметить особо, потому что он выглядит рантаймовым: сюда
он приходит только через `vite → postcss`, то есть в бандл не попадает.

Характер записей — отказ в обслуживании при разборе своих же файлов
(`brace-expansion`, `browserslist`) и чтение `.map`-файлов по
`sourceMappingURL` (`postcss`, `@babel/core`). Для сборочной машины это
риск цепочки поставки, а не риск для посетителя сайта. Вторая запись
`vite` — обход `server.fs.deny` на альтернативных путях Windows; машина
сборки здесь macOS и Ubuntu.

**Почему не обновлял.** `bun update` поднимает до «последних
совместимых», то есть двигает минорные версии десятка пакетов сборки
перед самой сдачей. Патч-версией закрывается не всё, а разделять
обновление по пакетам и проверять сборку на каждом — работа не на одну
ночь. NIGHT-RUN это и запрещает. В отчёт, как велит шаг 10.

Отдельно: GitHub при пуше показывает **27** уязвимостей на ветке по
умолчанию, `bun audit` — 37 плюс 4. Числа разные потому, что считают
по-разному (GitHub группирует по совету, `bun` — по пути зависимости).
Путать их не нужно: открытых **пакетов** два — `laravel/framework` и
сборочная цепочка фронтенда.

## Что вынести владельцу первым пунктом

1. **Вложения переписки доступны после удаления переписки** (S-13).
   Ссылка живёт дольше переписки, и убрать её изнутри сервиса нельзя.
   Это персональные данные людей, и это единственная находка, где
   последствие — утечка, а не неудобство.
2. **CSP работает только в режиме отчёта** (S-08), и в `script-src`
   стоят `'unsafe-inline'` и `'unsafe-eval'`. Пока так, CSP не защищает
   ни от чего — она собирает статистику. Это не дефект, а незаконченная
   настройка, но знать о ней стоит до открытия.
3. **HTML правовых страниц без санитайзера** (S-10) при трёх владельцах,
   один из которых посторонний живой человек.
4. **Laravel 11 → 12** (S-25): главная запись обойдена в коде, остальные
   три ждут мажорного обновления.
