## Решение

**CONDITIONAL GO** — для первой волны запуска: соцсеть, объявления,
каталог, сообщества, каналы, мессенджер, админка.

**NO-GO** — для приёма денег. Причина внешняя и известна: боевых ключей
эквайринга ВТБ нет, контур выплат не подключён (решение R6). За всю жизнь
сервиса прошёл **один успешный платёж из 59** и **ноль выплат
продавцам** (`docs/BIBLE.md` VII.2).

Отдельная оговорка, которая важнее процентов готовности: главная
возможность сервиса — безопасная сделка с доставкой — сегодня недоступна
никому, потому что **ни один живой продавец не заполнил пункт отправки**
(приёмка 27.09, подтверждено). Это данные, а не код.

## Финансовая сверка

Полностью — `docs/acceptance/night/FINANCE.md`. Все двенадцать сценариев
FIN-01…FIN-12 **PASS**, и ни один не проходил через банк.

Контрольный пример сходится: товар 1 000 ₽ → комиссия покупателя 50 ₽ →
покупатель платит 1 050 ₽ плюс доставка → продавцу 1 000 ₽. Пять величин
хранятся раздельно, в копейках, целыми. Старые сделки не пересчитываются
(колонка `fee_payer`). Комиссия берётся с товара, не с доставки — прод
отдаёт `safe_deal.base: "item"`.

Расхождений в учёте не найдено. Платежей, возвратов и выплат этой ночью
не проводилось ни одного.

## Восстановление

**Не проверялось этой ночью — `BLOCKED`.** Доступ к копиям требует входа
на боевой сервер или боевых ключей S3, и то и другое запрещено границами
ночи. Пошаговая инструкция для выполнения с владельцем — шесть шагов в
`docs/acceptance/night/MIGRATIONS.md`.

`docs/BIBLE.md` VI.1 утверждает «восстановление проверено байт в байт» —
это **прошлая** проверка, не эта ночь.

## Релиз

**Миграций в ночной ветке нет ни одной.** Ночная ветка не требует ни
одной операции над схемой боевой базы — проверено
`git diff --name-only origin/develop...night/2026-10-04 -- backend/database/migrations`
(пусто).

Процедура: слияние в `develop` делает человек кнопкой в GitHub (решение
NIGHT-RUN: `MERGE_TO_DEVELOP = нет`). Выкатка на прод — промпт У3 с
участием владельца, по шагам, с проверкой свежей резервной копии до
выкатки.

Откат: предыдущая сборка на месте, команда отката — в
`deploy/README.md`. Репетиция откката этой ночью не выполнялась, потому
что выкатывать было некуда.

Дымовая проверка после выкатки: `smoke-check.sh`, внутри него
`check-config-access.sh` и `check-live-money.sh`.
