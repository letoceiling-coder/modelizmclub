# ЧАСТЬ I. ЧТО ЭТО

## 1.1. Назначение

Социальная сеть и площадка объявлений для любителей масштабного моделизма: сборные модели, радиоуправляемая техника, диорамы, фигурки, инструмент, краски. Плюс нумизматика как отдельное направление.

Два контура в одном сервисе:

**Социальный** — лента, направления с чатами, сообщества, каналы, обзоры, переписка, друзья. Люди находят своих по интересу.

**Торговый** — каталог объявлений, безопасная сделка с доставкой СДЭК, рейтинг продавцов, платные размещение и продвижение.

## 1.2. Стек и адреса

| Бэкенд | Laravel 11.54, PHP 8.3, PostgreSQL |
| Фронтенд | React, TanStack Start, Nitro, bun |
| Сокеты | Reverb |

## 1.3. Внешние сервисы

Доставка СДЭК · эквайринг ВТБ · выплаты ВТБ по СБП · SMS через iqsms, в планах SMS-дисконт · Яндекс.Метрика и Вебвизор · Яндекс.Карты для выбора пункта · MAX, ВКонтакте, Яндекс для входа.

# ЧАСТЬ II. РОЛИ И ДОСТУП

## 2.1. Четыре роли

| Роль | Что может |
|---|---|
| `owner` | всё: 30 разделов админки, цены, роли, платежи, настройки |
| `moderator` | 12 разделов: пользователи, контент, объявления, доставки, модерация, заявки, категории, обзоры, уведомления, медиа, обращения, сводка |
| `category_admin` | только содержимое закреплённых за ним направлений |
| `user` | админки нет |

Администраторов направлений не больше десяти, порог настраивается. Один человек может вести несколько направлений.

## 2.2. Льготы — отдельно от роли

Две настройки на каждого человека, независимые от роли:

**Подписка не требуется** — флаг. Проходит все проверки подписки, сама подписка не создаётся.

**Бесплатных размещений** — число. Ноль — платит как все. Отдельное значение для «без ограничения».

Умолчания при назначении роли:

| Роль | Подписка | Размещений |
|---|---|---|
| `owner` | не требуется | без ограничения |
| `moderator` | не требуется | без ограничения |
| `category_admin` | не требуется | 10 |
| `user` | требуется | 0 |

**Это умолчания, а не жёсткая связь.** Владелец правит любое значение после назначения — так собирается особый случай вроде администратора «Нумизматики» с безлимитом.

## 2.3. Пять уровней доступа к действиям

| Уровень | Кто |
|---|---|
| `guest` | без входа |
| `auth` | вошёл, телефон не подтверждён |
| `verified` | телефон подтверждён |
| `subscription` | есть подписка |
| `staff` | сотрудник |

## 2.4. Инварианты доступа

Нарушение любого — блокирующий дефект.

```
Гость получает окно входа. Не paywall, не редирект на /login.
Без SMS получает окно подтверждения телефона. Не окно подписки.
С SMS без подписки получает окно подписки. Не окно телефона.
С подпиской не получает ни одного из четырёх окон.
Действие возобновляется после входа: нажал лайк гостем,
вошёл в окне — лайк поставился сам.
```

## 2.5. Решение 27.08 — что открыто вошедшим

Лайк, комментарий и репост доступны с уровня `auth` — то есть вошедшему с подтверждённым телефоном, без подписки. Это осознанное отступление от первоначального замысла: площадка должна жить, а не молчать.

За подпиской остаются: создание записи, создание видео, звонки, обзоры, сообщества и каналы.

## 2.6. Серверная проверка обязательна

**Скрытая кнопка защитой не является.** За цикл закрыли восемь обходов прав, и все были одного класса: проверка жила только в интерфейсе, а прямой запрос к API проходил.

Самый дорогой из них: модератор площадки мог подтвердить получение по чужой сделке, и деньги уходили продавцу.

Правило: в чужой сущности сотрудник площадки **модерирует**, но не действует от имени владельца.

# ЧАСТЬ III. ДЕНЬГИ

## 3.1. Подписки

| Тариф | Цена |
|---|---|
| Месяц | 99 ₽ |
| Полгода | 449 ₽ |
| Год | 599 ₽ |

Тарифы «Базовый» за 0 и «Pro» за 499 существуют в базе, выключены (`is_active = false`) и не отдаются публичным списком.

**Решение владельца 04.10: не удалять, оставить скрытыми, запретить покупку на сервере.**

Прежняя формулировка этого абзаца — «за „Pro“ платили шесть раз» — **проверена на боевой базе 04.10 и не подтвердилась.** Подписок на `pro` и `basic` ноль, платежей с этими тарифами ноль. Восемь платежей на 499 ₽, которые легко принять за «Pro», — это полугодовой тариф по старой цене (`plan_id 39`, тогда 499 ₽, сейчас 449 ₽), и ни один из них не завершился успехом: четыре брошены, два зависли, два отказаны. Разбор — `docs/acceptance/night/ROLES-AND-KEYS.md`.

## 3.2. Размещение и продвижение

| Услуга | Цена |
|---|---|
| Размещение объявления без подписки | 30 ₽ |
| Размещение с подпиской | 20 ₽ |
| Продвижение на 7 дней | 149 ₽ |
| Продвижение на 14 дней | 249 ₽ |
| Продвижение на 30 дней | 399 ₽ |

**Три числа, одно значение:** цена на странице тарифов = цена при оплате = значение в настройке. Расхождение — дефект.

Порядок оплаты размещения: персональная квота → тарифная квота → кредиты → деньги.

## 3.3. Комиссия безопасной сделки — решение 27.09

**Комиссию платит покупатель. Продавец получает полную стоимость товара.**

```
Товар                1 000 ₽
Комиссия 5%             50 ₽
Доставка               350 ₽
Покупатель платит    1 400 ₽
Продавец получает    1 000 ₽
```

Прежняя схема удерживала комиссию из выплаты продавцу. Существующие сделки по старой схеме **не пересчитываются**.

Все тексты про «удерживается из выплаты продавцу» должны быть заменены.

## 3.4. Бонусные баллы

Отдельная сущность, не кошелёк. Деньгами не выводятся.

Начисляются за приглашённого друга после **подтверждения им телефона**, не при переходе по ссылке. Размер и предел числа приглашений задаются в админке. Начальные значения: 100 баллов, предел 50.

Тратятся на размещение и продвижение объявлений. Курс в настройках, начальный — 100 баллов за размещение. Подписку баллами не покрываем.

## 3.5. Надбавка к доставке

Настройка в админке: процент или фиксированная сумма поверх тарифа СДЭК. Покупатель видит итоговую цену без разбивки. Владелец видит размер надбавки.

# ЧАСТЬ IV. РАЗДЕЛЫ

## 4.1. Лента

Записи с текстом, фотографиями, видео. Медиасетка по числу фотографий: 1 — во всю ширину, 2 — половины, 3 — одно большое и два, 4 — сетка 2×2, 5–6 — большое и ряд, 7–10 — сетка 3×3 с «+N» на последней.

Реакции, комментарии с ответами второго уровня, репост со своим текстом, сохранение, просмотрщик.

**Репост со своим текстом проходит модерацию** как новая запись — статус не копируется с исходной.

Фильтры: все, подписки, направления, сохранённое, запланированные.

Просмотр засчитывается при фактическом открытии, один раз в сутки на человека.

Записи канала попадают в общую ленту. Записи сообщества — нет.

## 4.2. Направления

Дерево до трёх уровней: Авиация → Планеры → ИЛ-6.

Правая панель «Найди своих» ведёт себя одинаково в ленте, сообществах, каналах и друзьях:
- клик по названию — страница направления;
- значок чата — чат этого уровня;
- шеврон — раскрытие подкатегорий в панели.

Страница направления, четыре вкладки в порядке: **Чат · Участники · Объявления · Записи**. По умолчанию открывается Чат — направление это место, где находят своих, а не вторая лента.

Записи и объявления включают вложенные уровни. Участники — только явно вступившие.

Чат направления виден в мессенджере.

## 4.3. Сообщества

Создание проходит модерацию — заявка попадает в **общую очередь** вместе с объявлениями и записями, не в отдельный раздел.

Вкладки: Стена, Чат, Мероприятия, Участники, О сообществе. Меню «Ещё» на восемь пунктов: уведомления, избранное, приглашение друзей, похожие сообщества, подробная информация, копирование ссылки, жалоба, выход.

Переключатель «проверять записи участников» в панели управления. Записи владельца и назначенных им модераторов публикуются сразу всегда.

Мероприятия: создание владельцем, «Пойду», напоминание за сутки, отмена, удаление. Два вида — события сообщества и события площадки, последние создаёт администратор и показываются баннером в ленте.

Предложка — **не работает**, форма показывает «отправлено», ничего не отправляя.

## 4.4. Каналы

Публикует только владелец и назначенные им администраторы. Остальные — комментируют, если владелец включил комментарии.

Счётчики подписчиков показывают реальные значения. Выдуманных чисел быть не должно.

## 4.5. Мессенджер

Шесть вкладок: Личные, Категорийные, Сделки, Сообщества, Архив, Звонки.

Диалог с новым сообщением поднимается наверх, **остальные не перерисовываются**. Сдвиг раскладки при отправке — ноль.

Счётчики непрочитанных растут и обнуляются. Разделитель непрочитанных. Возврат открывает последнее прочитанное.

Вложения, голосовые, эмодзи. Расшифровка голосовых выключена намеренно — нужен ключ SpeechKit.

Вход в переписку: **из объявления — любому вошедшему** (решение Ж3 от
09.10), из профиля и списка людей — по дружбе либо подписке.

Переписка по объявлению привязана к нему: название, цена и фото видны в
шапке чата и в строке списка диалогов, по нажатию открывается объявление.
Повторное «Написать продавцу» открывает ту же переписку, второго приветствия
в неё не добавляется. Оба продолжают разговор и после снятия объявления;
начать новую по снятому или по черновику нельзя. От рассылок — предел новых
переписок по объявлениям за сутки, значение из настроек, по умолчанию 20.
Жалоба и блокировка — из шапки переписки и из меню сообщения.

Каждый получает только свои события: подписка на канал сокета по идентификатору пользователя, с проверкой на сервере.

## 4.6. Объявления и каталог

Создание: три уровня категорий, обязательные поля, фото, способы доставки, габариты.

**Габариты обязательны при выборе СДЭК.** Типоразмеры S/M/L убраны — они подменяли введённое продавцом.

**Пункт отправки продавца обязателен** для СДЭК. Без него способ доставки не предлагается покупателю.

Переключатель «показывать мой номер», включён по умолчанию.

Раскрытие номера: гость получает окно входа, без SMS — окно подтверждения, с SMS — номер. **Номер не приходит в разметку до раскрытия.** Каждое раскрытие пишется в журнал, частота ограничена двумя порогами — минутным и часовым.

Карточка в каталоге показывает рейтинг продавца: аватар, имя, звёзды, число отзывов.

Проданное объявление уходит из каталога — статус `Sold`.

## 4.7. Безопасная сделка

Путь: создание → оплата → `paid` → отгрузка с трек-номером → `shipped` → `delivered` → подтверждение покупателем → `completed` → оценка.

**Подтверждает получение покупатель.** Продавец отмечает отправку. Семь дней автосписания — защита на случай молчания покупателя.

Спор с файлами, деление суммы, отмена до отгрузки, возврат.

Отмена доходит до СДЭК — заказ отменяется у перевозчика.

Статус отправления обновляется вебхуком и приходит живым событием без перезагрузки.

## 4.8. Кабинет

Профиль: имя, город с подсказками, «о себе», направления, аватар, обложка, рейтинг.

Тринадцать разделов настроек. Баланс, пополнение, история платежей, вывод средств. Избранное, друзья, приглашения, обратная связь.

Отзыв продавцу может оставить только покупатель и только по завершённой сделке, один раз.

## 4.9. Админка

Тридцать разделов. Монетизация разделена на вкладки: тарифы и цены, оплаты, бухгалтерия, акции и промокоды.

Категории деревом с раскрытием, сортировка по алфавиту, иконки правятся и при создании, и при изменении.

Роли и доступ: назначение, привязка категорий, правка льгот, права галочками поверх роли.

Промо-пулы: период действия календарём, ограничение мест, круг доступа выбором людей, автоматический старт и завершение.

**Каждое изменяющее действие пишется в аудит.**

## 4.10. Правовой раздел

Хаб `/rules` с группировкой: деньги и услуги, правила площадки, данные и приватность, о сервисе.

Страница тарифов — **цены берутся из настроек, не из текста**. Это документ, на который ссылается оферта.

Реквизиты оператора, ссылки в подвале, упоминание рекомендательных технологий, если лента ранжируется.

# ЧАСТЬ V. ПРАВИЛА РАЗРАБОТКИ

## 5.1. Процесс

```
Каждая задача — своя ветка в отдельном рабочем дереве.
Тесты с доказательством откатом: проверка, которая не краснеет
при откате правки, ничего не проверяет.
Независимое ревью субагентом в чистом контексте.
Отчёт: что было, что стало, чем доказано.
Вливание и выкатка по зелёному CI на том же SHA.
После выкатки — проверка содержимым, не кодом ответа.
```

## 5.2. Не создавай второго, если есть первое

`PostCard` · `ui/UserAvatar` · `lib/gate` · `formatDate` · `Appear` · `ReducedMotionSwitch` · `ComplaintDialog` · `GuestSectionStub` · `categoryPlaceholder` · `askConfirm` · `EntityHeader` · `EntityTabs` · `EntityRow` · `PhotoEditorDialog` · `HorizontalScrollNav` · `InAppNotify` · `AuditService` · `BonusPointsService` · подсказки городов · очередь модерации · механизм квот · токены из `docs/design-system.md`.

## 5.3. Оформление

Отступы по шкале 4/8/12/16/24/32. Слои только токенами: sticky 10, dropdown 20, banner 30, overlay 40, modal 50, popover 55, toast 60, gate 70, call 80.

Кольцо фокуса внутрь с `outline-offset: -2px` — снаружи его обрезают прокручиваемые ряды.

`framer-motion`: `initial` не задавать на первом рендере, использовать `Appear` и `ReducedMotionSwitch`. После сборки проверять `grep -c 'opacity:0'` в серверной разметке.

Ширины проверки: 375, 768, 1024, 1440, 1920.

## 5.4. Данные

Массовые изменения — только с сухим прогоном, независимой проверкой выборки **другим запросом** и раскладкой заказчику до записи.

Команды, меняющие данные, отказывают при `APP_ENV=production` или требуют явного подтверждения.

Миграции обратимы, `down()` непустой, эталон схемы пересобирается.

Повышение роли для проверки возвращается **в том же заходе**, снятие прав с себя — последним действием.

## 5.5. Ловушки замера

Собраны из ошибок, сделанных в этом проекте. Каждая стоила дня.

```
Отрицательные утверждения требуют полного чтения.
«Этого нет», «не вызывается», «закрыто» — трижды оказывались
неверными.

Чинить то, что происходит, а не то, что названо в отчёте.

Журнал выкатки писал DONE при упавшей сборке, smoke отвечал 200
старым кодом. Проверять содержимым.

Проверка, которая не умеет провалиться, опаснее отсутствующей.

Подготовка данных тем же механизмом, который сторожишь, даёт
зелёную проверку при сломанной модели.

Экранирование в SQL сворачивается: ilike по кириллице даёт
ложный ноль, юникод в JSON экранирован.

Замер в браузере читает не только main — окна рисуются порталом
снаружи.

querySelector('header') берёт мобильную шапку.

Прокручиваемый контейнер может быть не документом.

Кириллица в именах переменных ломает скрипт молча, bash -n
её не ловит.

\s в регулярном выражении включает перевод строки и табуляцию.

textContent, а не innerText. grep -a. Хит-зоны с ::before
и ::after. Выдержка не меньше десяти секунд.

Демо-режим на localhost включается сам — замеры без данных
ничего не доказывают.

Параллельные прогоны упирают API в 429 и дают ложные дефекты.

Смотреть перед перезаписью файла, а не после.
```

## 5.6. Честность

Заявление — не доказательство. Не воспроизвелось — так и писать. Ошибся — сказать, не дожидаясь, пока заметят.

# ЧАСТЬ VI. ИНФРАСТРУКТУРА

## 6.1. Что работает

Автоматические бэкапы с выгрузкой в S3, восстановление проверено байт в байт. Откат проверен в бою. Четыре сверки после каждой выкатки: схема, карта прав, nginx, доступ к конфигу. Планировщик с замками по интервалу. Права на секреты закрыты. Журналы переживают перезагрузку. Сторож диска на 80 и 90 процентах. Хуки против работы в общем дереве.

CI не читается без `GH_TOKEN`. Правки прав из консоли идут мимо аудита. Нагрузочного замера не было ни разу — всё измерено на демо-данных.
