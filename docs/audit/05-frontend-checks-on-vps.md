# Проверки фронтенда на сервере: где гонять и чему верить

08.09.2026. Замер, а не рассуждение: все числа ниже сняты на боевом VPS в тот
же день.

**Коротко.** `tsc` в основном чекауте на сервере даёт 141 ошибку. Это не
состояние кода, а состояние каталога. В том месте, где сборку делает деплой,
ошибок **39** — ровно тот же порог, что на машине разработки.

---

## Про документ, которого нет

Задача была поставлена как «обнови `docs/audit/06-server-tests`». Такого файла
нет и не было: в `docs/audit/` лежат `01-baseline`, `02-lighthouse`,
`03-execution-pack`, `04-pre-launch`, и по всей истории git файл с таким
именем не заводился ни разу. Ближайшее по смыслу —
`deploy/scripts/run-server-tests.sh`, но он гоняет только PHPUnit и `tsc` не
трогает вовсе.

То есть число 141 пришло не из документа, а из ручного запуска в неверном
каталоге. Поэтому запись сделана здесь, новым файлом, и продублирована в
`deploy/README.md` — там её найдёт тот, кто пришёл выкатывать.

## Как устроен боевой фронт

```
/var/www/modelizmclub/frontend/.output
  → симлинк на .worktrees/frontend-<release>/frontend/.output
```

Сервис `modelizmclub-frontend.service` работает с `WorkingDirectory` в
основном чекауте, но весь код читает через этот симлинк. Сборка живёт в
отдельном git worktree, который деплой заводит на каждый релиз и хранит в двух
последних экземплярах — для отката.

Состояние на 08.09 после выкатки `610b9819`:

| Каталог | Что внутри |
| --- | --- |
| `.worktrees/frontend-20260908130217` | текущий релиз: `node_modules` 553 МБ (519 пакетов), `routeTree.gen.ts` 55 848 Б, `.output` |
| `.worktrees/frontend-20260908110419` | предыдущий релиз, цель отката (`.worktrees/PREVIOUS`) |
| `frontend/` (основной чекаут) | `node_modules` от 13.08 (340 пакетов), `routeTree.gen.ts` **отсутствует** |

## Замер

| Где | `tsc --noEmit` |
| --- | --- |
| основной чекаут | **141** |
| свежий worktree, зависимости поставлены, **до** `bun run build` | 124 |
| тот же worktree **после** сборки | **39** |
| worktree текущего релиза | **39** |

Сборка в свежем дереве: `bun install --frozen-lockfile` — 2,1 с (823 пакета),
`bun run build` — 1 мин 10 с, код выхода 0.

Раскладка 39 ошибок по кодам: `TS2322` — 13, `TS2345` — 9, `TS2741` — 6,
`TS2739` — 4, `TS2740` — 3, `TS2352` — 2, прочие — 2. Это тот же порог, что
записан в `.github/workflows/ci.yml`.

### Откуда берётся разница

**124 против 39 — нет `src/routeTree.gen.ts`.** Файл создаёт сборка, в git он
не хранится. Без него не разрешается ни один импорт маршрута, и tsc насчитывает
ошибки в файлах, где ничего не сломано. Ровно поэтому в CI шаг `Build` стоит
**перед** `tsc`, и там об этом написано прямо: «без него каждый импорт маршрута
резолвится в ничто, и число ошибок — выдумка».

**141 против 124 — устаревшие зависимости.** В основном чекауте 340 пакетов от
13 августа против 519 в worktree.

## Нужен ли `node_modules` в основном чекауте

Нет.

- Nitro собирает сервер самодостаточным: в `.output/server/node_modules` один
  `tslib`, весь сервер — 11 МБ.
- `server-graceful.mjs` импортирует только `node:net`.
- Работающий процесс не держит ни одного открытого файла и ни одной карты
  памяти под `frontend/node_modules` — проверено по `/proc/<pid>/fd` и
  `/proc/<pid>/maps`, ноль совпадений.
- Ни один скрипт в `deploy/` к этому каталогу не обращается.

Это наследство эпохи до worktree-сборок. Обновлять его незачем. Удалить можно —
сломается только ручной запуск tsc в основном чекауте, который и так даёт
неверное число.

## Как проверять правильно

```bash
cd /var/www/modelizmclub
W=.worktrees/frontend-probe-$(date +%H%M%S)
git worktree add --detach "$W" HEAD
cd "$W/frontend" && bun install --frozen-lockfile && bun run build
npx tsc --noEmit | grep -c "error TS"     # ждём 39
cd /var/www/modelizmclub && git worktree remove --force "$W" && git worktree prune
```

**Чего не делать: `bun run build` в живом worktree** — том, на который смотрит
симлинк. Это та самая авария, ради которой сборку вынесли в отдельное дерево:
14.07 на стенде neeklo запрос, попавший в середину сборки, получил удалённый
chunk и error boundary. Куда смотрит симлинк:
`readlink -f /var/www/modelizmclub/frontend/.output`.

`tsc --noEmit` в живом worktree безопасен — он ничего не пишет.

## Замечено по дороге, не чинилось

`deploy/scripts/run-server-tests.sh` вызывает `php artisan config:clear` на
сервере. До 08.09 это укладывало API на шесть минут: `.env` был `600 root`, и
php-fpm его не читал. Права починены (`640 root:www-data`), и теперь чистка
безопасна — но команда осталась в скрипте, а правило проекта велит на проде
кеш конфигурации не трогать. Если после неё кеш пересоберут от root без
`chown root:www-data`, сайт ляжет уже по другой причине: Laravel делает
`require` существующего, но нечитаемого файла без запасного пути.
