## Метод

Каждое действие вызвано настоящим запросом к боевому API под каждым
состоянием. Ворота меряются кодом отказа: `401` — окно входа,
`403 phone_not_verified` — окно телефона, `403 subscription_required` —
окно подписки.

Для действий, создающих содержимое, тело отправлялось **заведомо
неполным**. Тогда `422` означает «ворота пройдены, отказала проверка
полей» — и ничего не создаётся. Для переключателей (лайк, закладка,
избранное, подписка, вступление) успех отменялся обратным запросом сразу
же, в том же проходе.

Состояния подтверждены замером, а не взяты из названий токенов:

| Состояние | id | Чем подтверждено |
| --- | --- | --- |
| гость | — | без заголовка, `/users/me` → 401 |
| без SMS | 1274 | `role=user`, `phone_verified=false` |
| с SMS | 1275 | `role=user`, `phone_verified=true`, подписки нет |
| с подпиской | 1276 | `phone_verified=true`, `is_active=true` |
| модератор | 1207 | `role=moderator` |

**Двух состояний из семи нет.** Владелец и администратор направления
требуют выдачи роли, а запись на прод мне закрыта. Эти два столбца не
проверены — не «в порядке», а не проверены.

## Инварианты

**1. Гость получает окно входа, не paywall и не редирект — держится.**
Все 22 действия отвечают `401` с телом «Войдите в аккаунт, чтобы
продолжить». Ни одного `402`, ни одного `subscription_required`, ни
одного перенаправления. Гость paywall не видит нигде.

**2. Без SMS — окно телефона, ни разу окно подписки — держится.**
Все закрытые действия отвечают `403` с кодом `phone_not_verified`. Кода
`subscription_required` под этим состоянием не встретилось ни разу.

**3. С SMS без подписки — окно подписки, ни разу окно телефона —
держится.** Закрытых действий два: создание записи и создание видео, оба
отвечают `403 subscription_required` с текстом «Оформите подписку, чтобы
публиковать контент». Кода `phone_not_verified` под этим состоянием нет
нигде.

**4. С подпиской — ни одного из четырёх окон — держится.** Ни одного
`401` и ни одного `403`. Везде либо `200`, либо `422` от проверки полей.

**5. Возобновление действия после входа — не проверено.** Это поведение
браузера: `gate.intent` в `sessionStorage`, `resumeIntent()` после
закрытия окна. Замером по API его не увидеть. Проверка — в части про
сквозные пути.

## Что из этого стоит обсудить

Находок, нарушающих инварианты, нет. Но два наблюдения требуют вашего
подтверждения, что так и задумано.

**Публиковать запись нельзя без подписки, а разместить объявление —
можно.** «Создать запись» и «создать видео» под «с SMS» дают
`403 subscription_required`. «Разместить объявление» под тем же
состоянием даёт `422`, то есть ворота пройдены. Асимметрия объяснимая
(объявление — источник дохода площадки, запись — нет), но она означает,
что человек без подписки может завести объявление и не может написать
запись о нём же.

**Четыре чтения открыты без подтверждения телефона:** мессенджер,
уведомления, друзья и раздел сделок отвечают `200` уже на состоянии «без
SMS». Это согласуется с правилом проекта «чтения остаются открытыми», и
дефектом не является — но значит, что человек, не подтвердивший телефон,
видит списки, в которых ничего не может сделать.

**Модератор ведёт себя ровно как подписчик** во всех 22 действиях.
Отдельной ступени у него нет — staff обходит проверку подписки, и это
видно по совпадению столбцов.

## Что не проверено

- Два состояния из семи: владелец и администратор направления. Нужна
  выдача роли на проде.
- Пятый инвариант — возобновление действия после входа.
- Поведение окон на экране: проверялся API, а не то, какое окно
  нарисовалось. Совпадение кода и окна закреплено кодом фронта
  (`validationErrors.ts`, `chat-attachments.ts` разбирают именно эти два
  кода), но глазами не подтверждено.
