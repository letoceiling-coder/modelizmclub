# Гидратация: первый кадр совпадает с серверным

Разбор D8 (React #418), 14.09.2026. Цель документа — чтобы следующий человек
узнал шаблон по симптому и не искал причину заново.

## Что происходит

Страница рисуется дважды: на сервере (Node, пояс `Etc/UTC`, без
`localStorage`, без экрана, без токена) и в браузере при гидрации. React
сравнивает первый кадр браузера с серверной разметкой. Если они различаются
хоть в одном узле, React бросает `Minified React error #418`, выбрасывает
серверное дерево и перерисовывает его на клиенте. Пользователь ничего не
видит, но теряет всё, ради чего страницу рисовал сервер: первый экран строится
заново, LCP уезжает, соседние блоки сдвигаются.

**Шаблон.** Любое значение, которое на сервере и в браузере разное, не должно
решать, что нарисовать в первом кадре. Разное бывает:

| Что | На сервере | В браузере |
| --- | --- | --- |
| токен (`mc_token` в localStorage) | нет — посетитель гость | есть — вошедший |
| localStorage вообще | пусто | сохранённые настройки, избранное, история |
| часовой пояс | `Etc/UTC` | пояс человека, чаще Москва |
| тема | неизвестна, `systemPrefersDark()` → тёмная | светлая или тёмная |
| размер экрана | нет экрана | 375…1440 |
| время | момент отрисовки на сервере | момент гидрации, секунды спустя |

## Как узнать

- В консоли продакшена — `Minified React error #418; …?args[]=HTML` или
  `args[]=text`. Номер один на все расхождения, узла он не называет.
- Узел покажет dev-сборка: `cd frontend && TZ=UTC VITE_API_BASE_URL=https://api.modelizmclub.ru/api/v1 VITE_DEMO_MODE=false node_modules/.bin/vite dev`.
  Браузер открывать с `timezoneId: "Europe/Moscow"` и нужным localStorage.
  Сообщение `Hydration failed…` печатает дерево с `+` (клиент) и `-` (сервер).
- React сообщает только **первое** расхождение. После починки — замер снова:
  за первым часто прячется второе.
- Некоторые расхождения dev не показывает (гидрация там медленнее). Тогда —
  боевая сборка и сравнение разметки без JS с DOM после гидрации.

**Ловушки замера**, на которых 14.09 чуть не было ложного «чисто»:

1. Сервер и браузер в одном поясе. Мак — `Asia/Bangkok`, локальный
   `node .output/server/index.mjs` — тоже он: даты совпадают, дефект невидим.
   Сервер — `TZ=UTC`, браузер — `Europe/Moscow`.
2. Пустой localStorage. Замер «вошедший» с одним токеном не видит
   расхождений у человека, у которого сохранены тема, избранное, настройки
   колонки. Замер делать и с ними.
3. Счётчик ошибок только по `console`. #418 приходит событием `pageerror`,
   консольный обработчик её пропускает и показывает ноль.

## Причины, найденные в D8

### 1. Токен читается при отрисовке

`GuestAccessProvider`: `const isGuest = !getToken() || …`. Сервер токена не
видит → гость; браузер уже в первом кадре → вошедший. Первым расходился пункт
«Пригласить друга» в боковом меню (`{!isGuest && <InviteFriendNavLink />}`).
Затронуто всё, что зависит от `isGuest`: на проде 17 страниц из 21 у
вошедшего. То же — `isAuthenticated()` в `InviteBlock`, `/referral`,
`UserMenu`, `VerificationBanner`, `AuthShell`.

**Починка:** `useHasToken()` (`src/hooks/use-has-token.ts`) — до конца
гидрации отвечает как сервер, сразу после — по токену. В обработчиках и
эффектах по-прежнему `getToken()`.

### 2. Дата форматируется в поясе того, кто рисует

`formatDate(…, "absolute")` пишет время через `getHours()` — в поясе процесса.
Сервер (UTC) пишет «14:27», браузер в Москве — «17:27». На `/rules` так
расходилась «Редакция от …».

**Починка:** `formatAbsoluteInZone(date)` (`src/lib/format/date.ts`) — тот же
формат, пояс фиксирован (`Europe/Moscow`). Для относительного времени —
`<TimeAgo>`: до гидрации он рисует заглушку с `suppressHydrationWarning`.

### 3. Тема в провайдере

`ThemeProvider` создаёт состояние из `localStorage` и `matchMedia`. Сервер
считает тему тёмной, браузер со светлой — светлой. Переключатель в подвале
лендинга рисовал разные иконки (солнце и луну).

**Починка:** в `ThemeToggle` обе иконки в разметке, видна одна классом
`dark:` — класс `dark` на `<html>` ставит скрипт из `__root` до первой
отрисовки. Инициализацию провайдера **не трогать**: эффект сразу пишет выбор
в localStorage и затёр бы сохранённую тему. Где нужен именно выбор (radio
на `/settings/appearance`) — `useHydrated() ? preference : "system"`.

### 4. `InviteBlock` на `/subscription` рисовался только клиентом

`InviteBlock`: `me.id === GUEST_USER.id && !isAuthenticated()`. Сервер —
кнопка для гостя, браузер вошедшего — блок со ссылкой. Частный случай
причины 1, но в другом компоненте и не через `isGuest`, поэтому первая
починка его не закрыла.

**Починка:** та же — `useHasToken()`.

### 5. Дата в блоке «О канале»

`AboutPanel` на странице канала: `formatDate(channel.createdAt, "absolute")`.
Канал создан в 17:27 МСК, сервер писал 14:27. Частный случай причины 2.

**Починка:** `formatAbsoluteInZone`.

### Найдено сверх этого — состояние сервера, накопленное между запросами

Страница канала давала #418 **только после** того, как тот же процесс Node
отрисовал страницу сообщества. Карточка записи брала автора из модульного
реестра `lib/user-registry` (`post.author ?? userById(post.authorId)`), а
`PostItem` клал владельца канала в реестр эффектом — уже после первого кадра.
Модуль на сервере живёт весь процесс: участники сообщества, записанные при
чужом запросе, оставались в реестре, и следующий канал рисовался с настоящим
именем. В браузере реестр при гидрации пуст — «Пользователь».

На проде процесс живёт сутками, поэтому ошибка там почти постоянная, а на
свежем локальном сервере — не воспроизводится вовсе. Это ещё и утечка: ответ
одному посетителю зависел от того, кого сервер обслуживал до него.

**Починка:** данные — у источника (`toFeedPost` кладёт автора в запись);
`registerUser` на сервере ничего не делает.

**Ловушка замера:** проверять страницы по одной на свежем сервере мало.
Нужен прогон по многим страницам подряд на одном процессе — так он
«прогревается», как на проде. Модульное состояние (кэши, реестры, сторы) —
первый подозреваемый, когда ошибка зависит от порядка страниц.

### Найдено сверх этого — сохранённое в localStorage

Проявляется только у тех, у кого что-то сохранено; замер с пустым браузером
их не видел.

- **Правая колонка** (`DirectionsRightRail`): сортировка и свёрнутость
  читались в инициализаторе `useState` → `/feed`, `/communities`.
- **Избранное** в `lib/store.ts` читалось при загрузке модуля → счётчик на
  иконке «Избранное» в шапке расходился на всех страницах с шапкой.
- **`/settings/history`**: `useState(getViewHistory)` — список из
  localStorage против пустого серверного.
- **`/settings/appearance`**: отмеченная сохранённая тема против «системной».

**Починка:** первый кадр — значения по умолчанию, как у сервера; сохранённое
— в `useEffect` после монтирования (для стора — `loadPersistedFavorites()` и
`loadNavExpanded()` из `AppLayout`). **Запись в localStorage не начинается
раньше чтения**: иначе эффект записи на монтировании затрёт выбор человека.
В колонке эффект чтения стоит после эффектов записи именно поэтому.

## Как надо

```tsx
// токен
const hasToken = useHasToken();              // не getToken() в теле компонента

// любое браузерное значение
const hydrated = useHydrated();
const preference = hydrated ? stored : "system";  // до гидрации — как сервер

// сохранённое в localStorage
const [sort, setSort] = useState<SortMode>("alpha");
useEffect(() => { if (localStorage.getItem(KEY) === "popular") setSort("popular"); }, []);

// дата на странице, которая приходит с сервера
formatAbsoluteInZone(iso)                    // не formatDate(iso, "absolute")
<TimeAgo iso={iso} />                         // относительное время

// тема — классом, а не условием
<Sun className="hidden dark:block" /><Moon className="block dark:hidden" />
```

Цена — у вошедшего и у человека с сохранёнными настройками первый кадр
совпадает с серверным, а своё состояние появляется кадром позже. Это лучше,
чем #418: там перерисовывается вся страница.

## Почему нет правила линта

Попробовано 14.09: правило, которое ищет localStorage, `getToken()`,
`matchMedia`/`innerWidth` и `formatDate`/`getHours()` в теле компонента, хука,
инициализаторе `useState` и колбэках `map`. На кодовой базе — 48 срабатываний
в 38 файлах, настоящих среди них единицы (колонка). Остальное — даты в данных,
которые грузятся в браузере после первого кадра и на сервере не рисуются,
решения о загрузке данных, всплывающие меню. При этом правило не видит
`useState(getViewHistory)` (функция ссылкой) и чтение при загрузке модуля
(`lib/store.ts`). Слишком грубое для ошибки и неполное — оставлено на
внимательности и замере (см. «Как узнать»).
