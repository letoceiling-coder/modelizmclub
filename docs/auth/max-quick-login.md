# Быстрый вход и регистрация через MAX

Инструкция для оператора и описание рабочей схемы на modelizmclub.ru.

Дата: 2026-08-24. Источники: [dev.max.ru](https://dev.max.ru), бот [@se13448473_1_bot](https://max.ru/se13448473_1_bot).

---

## Главное

У MAX **нет website-OAuth**, как у VK ID и Яндекс ID. Вход на сайт идёт через **чат-бота**:

1. На `/login` или `/register` человек нажимает MAX.
2. Сайт создаёт одноразовую сессию и открывает бота: `https://max.ru/se13448473_1_bot?start={session}`.
3. Бот предлагает **«Поделиться номером и войти»** (MAX не отдаёт телефон сам и запрещает логинить одним диплинком). Можно «Войти без номера».
4. Webhook `https://api.modelizmclub.ru/api/v1/webhooks/max` получает подтверждение или контакт.
5. Создаётся или находится пользователь (`provider=max`), выдаётся Sanctum-токен.
6. Страница логина забирает токен опросом статуса **или** человек возвращается по ссылке из бота.

Телефон из профиля MAX **сам не приходит**. Его даёт только кнопка `request_contact`. Если подпись `hash` совпадает (HMAC-SHA256 токена бота по `vcf_info`), номер пишется в профиль и ставится `phone_verified_at` — SMS для этого номера не нужен. Пересланный контакт без `hash` не принимаем. «Войти без номера» оставляет телефон пустым: тогда подтверждение по SMS на сайте, как раньше.

**Цифровой ID** и мини-приложение для входа на сайт не используются.

Мини-приложение в кабинете бота **не заполняйте**.

|------|------------|
| `MAX_BOT_TOKEN` | Токен бота (секрет, не в git) |

После выкладки кода на сервер:

```bash
# Сертификаты Минцифры (иначе curl error 60 к platform-api2.max.ru)
curl -fsSL -o /usr/local/share/ca-certificates/russian_trusted_root_ca_pem.crt https://gu-st.ru/content/lending/russian_trusted_root_ca_pem.crt
curl -fsSL -o /usr/local/share/ca-certificates/russian_trusted_sub_ca_pem.crt https://gu-st.ru/content/lending/russian_trusted_sub_ca_pem.crt
update-ca-certificates

cd /var/www/modelizmclub/backend
php artisan config:clear
php artisan config:cache
php artisan max:register-webhook
```

## Поток в коде

| Место | Роль |
|-------|------|
| `OAuthButtons.tsx` | VK/Яндекс — ссылки OAuth; MAX — POST start + опрос статуса |
| `POST /api/v1/auth/oauth/max/start` | Сессия 10 минут, URL бота |
| `GET /api/v1/auth/oauth/max/status` | `pending` / `awaiting_confirm` / `ready` (+ token один раз) / `denied` / `expired` |
| `GET /api/v1/auth/oauth/max/redirect` | Fallback без JS: 302 в бота |
| `POST /api/v1/webhooks/max` | `bot_started`, `message_callback`, `message_created` |
| `MaxAuthService` | Сессия в cache, подтверждение, `OAuthService::resolveUser('max')` |
| `php artisan max:register-webhook` | Подписка webhook в MAX API |
| `MaxNotificationService` | Все Laravel-уведомления дублируются в чат бота |

Пользователь MAX: синтетический email `max_{id}@oauth.modelizmclub.local` (в настройках не показывается), почта считается подтверждённой. Телефон — только после `request_contact` с валидным `hash`.

**Уведомления в MAX.** Если у пользователя есть `user_oauth_accounts.provider=max` (вход через MAX или привязка аккаунта), каждое уведомление сайта уходит ботом в MAX: заголовок + текст и кнопка «Открыть» на страницу сайта. Сбой MAX API не ломает исходное действие (заявка в друзья, сообщение и т.д.).

## Что нужно заранее

- Юрлицо, ИП или самозанятый — **резидент РФ**. Физлицу и нерезиденту верификация закрыта.
- Верификацию проходит **руководитель** (единоличный исполнительный орган) или человек с правом первой / единственной подписи. Сотрудник «просто с телефоном компании» не пройдёт.
- Аккаунт MAX на том же номере, с которым заходите в кабинет.
- Госуслуги: роль **Руководитель**, данные ЕГРЮЛ/ЕГРИП свежие.
  - Если несколько организаций — выбрать нужную.
  - При сбое: Госуслуги → профиль организации → Данные организации → **Обновить** и подождать (минуты–час, редко до суток).
- Для карточки бота:
  - логотип 500×500 px, до 5 МБ, `.jpg` / `.jpeg` / `.png`, без чужих брендов и 18+;
  - название 1–59 символов, без эмодзи;
  - описание до 200 символов;
  - сайт: `https://modelizmclub.ru`.

Лимит ботов: организация / ИП — 5, самозанятый — 2.

Поддержка MAX: чат «Поддержка MAX для бизнеса» или `partner_support@max.ru` (ИНН, телефон, шаги, скрин ошибки).

## Шаг 2. Создать профиль и пройти верификацию

Бот пишет: «Создать канал можно только после верификации вашего профиля». Без верификации **чат-бот тоже нельзя создать**.

1. Выберите тип профиля: организация / ИП / самозанятый.
2. Пройдите **верификацию через Госуслуги** (в мини-приложении пока только так).
3. Подтвердите компанию или ИП как руководитель.

Готово, когда бот напишет, что профиль подтверждён, и откроется выбор сервисов: чат-бот, канал, мини-приложение.

## Шаг 3. Создать чат-бота для входа на сайт

В мини-приложении или на платформе для партнёров:

1. Раздел **Чат-боты** → **Создать**.
2. Заполните карточку:

| Поле | Что указать |
|------|-------------|
| Логотип | Квадрат 500×500, без чужих брендов и 18+ |
| Название | Например `МоДелизМ` |
| Ник | Генерируется сам: `idИНН_bot` (юрлицо/ИП) или `se…_bot` (самозанятый). Сменить нельзя |
| Сайт | `https://modelizmclub.ru` (в профиле бота не светится — продублируйте в описании) |
| Описание | Зачем бот: вход и регистрация на modelizmclub.ru |

3. Нажмите **Создать**. Статус: «на модерации». Пока идёт проверка, настройки не меняются.

Ник станет ссылкой вида `https://max.ru/idИНН_bot`.

Документация: [Создание и модерация чат-бота](https://dev.max.ru/docs/chatbots/bots-create/create).

## Шаг 5. Скопировать токен бота

Это главный секрет. Без него вход на сайт не собрать.

**В мини-приложении / боте «MAX для бизнеса»:** команда **Получить токен** (появляется после модерации).

**На сайте платформы:** Чат-боты → нужный бот → **Расширенные настройки → Настроить** → поле токена.

Пример вида: `AAHdqTcvCH1vGWJxfSeofSAs0K5PALDsaw`.

Токен — полный доступ к боту. Не в чат, не в git, не в скриншот. Если утёк — там же кнопка обновления.

Документация: [Управление ботом](https://dev.max.ru/docs/chatbots/bots-create/manage).

## Чего в MAX делать не нужно

- Не искать Client ID / Client Secret / Redirect URI — для сайта их нет.

- Не создавать канал и не брать метку А+ — для входа не нужны.
- Не ждать Client ID — для сайта их нет. Вход уже через бота.

## Реализация на сайте

Рабочий путь: бот + webhook, не OAuth2 и не мини-приложение.

1. На `/login` человек нажимает MAX.
2. Открывается бот `https://max.ru/se13448473_1_bot?start={session}`.
3. Он нажимает «Войти».
4. Сервер создаёт сессию Sanctum, как после VK.

SMS для gated-действий обязателен.

### Мини-приложение — указывать ссылку?

**Нет, пока оставьте поле пустым** и не нажимайте «Сохранить» с `https://`.

Поле «Мини-приложение» на `business.max.ru/self/chat-bots/settings` — это HTTPS-страница, которую MAX откроет **внутри мессенджера**. Туда нужна наша страница, которая читает `window.WebApp.initData` и обменивает его на сессию сайта. Такой страницы ещё нет.

Если вписать `https://modelizmclub.ru` сейчас, в боте откроется обычный сайт без входа через MAX.

Первый рабочий вход — **без мини-приложения**. Ссылку добавим только если понадобится WebApp внутри MAX.
